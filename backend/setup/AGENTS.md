# backend/setup — plant-scoped, versioned, observation-only setup (changeover) persistence

## What lives here

- **`routes.py`** (433 lines) — 17 routes: 16 under `/setup/{plant}/*` plus `PUT /plant/{plant}/setup-active`:
  - `PUT /setup/{plant}/active` (`set_setup_active`) — **vestigial but retained** (Workstream D2, 2026-08-20): used to be the "Include setup times in optimizer" write path; see Key invariants below.
  - `GET /setup/{plant}` (`get_setup`) — one authorized plant's complete setup snapshot (definition + matrix + machine states), never a cross-plant aggregate; attaches `plant_active` (from `plants.setup_active`, the real activation gate). `machine_rows`/`machine_states`/`overrides` are scoped to the plant's live machine roster (registered machines, or machines with at least one retained order — which may still include a renamed/decommissioned code for as long as its historical orders remain in the database, a materially tighter bound than every setup-matrix row ever recorded, even if not a perfectly current one) — not every machine code ever recorded for this plant (`Code_Review_09_01.md` P1-9, resolved 2026-09-04).
  - `PUT /plant/{plant}/setup-active` (`set_plant_setup_active_route`) — the **current** "include setup times in optimizer" write path, persisting the plant-level flag onto `plants.setup_active`.
  - `GET /setup/{plant}/coverage` (`get_setup_coverage`) — bounded Stage 0 transition coverage. Each of `reachable`/`observed` carries `total_pairs`, `covered_pairs` (rows + the diagonal), **`default_covered_pairs`** (covered only by a value default, never double-counted with a row) and `missing_pairs` = true gaps (no row, no default, off-diagonal). Since 2026-10-27 the reachable missing page is **to-state-major** (it used to be row-major by from-state).
  - `GET /setup/{plant}/matrix-rows` (`get_setup_matrix_rows`) — bounded, from-state-scoped page of effective matrix rows (the O(states²)-avoidance endpoint).
  - `GET /setup/{plant}/missing-pairs.csv` (`export_setup_missing_pairs`) — CSV export of one bounded, selectable page of missing canonical pairs (UTF-8 BOM + spreadsheet-formula guard via `backend/csv_util.py`, `csv_row`).
  - `PUT /setup/{plant}/definition` (`save_setup_definition`) — master-data-owner write for a plant's ordered signature definition.
  - `POST /setup/{plant}/matrix/import` (`import_setup_matrix`) — validated mass-upload, plant-wide or single-machine-scoped.
  - `PUT /setup/{plant}/value-defaults` (`save_setup_value_defaults`) — admin-only upsert/delete of one signature field's value defaults: body `{signature_version, field_key, entries: [{value, setup_min | null}]}` (null deletes; at most 2,000 entries; minutes 0-10,080). One transaction under the definition row lock; a stale version is 409, a `field_key` outside the plant's definition or a non-object body is 400. Audited as `setup.value_defaults_write` (`_ADMIN_WRITE_OPERATIONS` in `brain.py`; the log records the `field_key` and upsert/delete counts, never the values or minutes).
  - `GET /setup/{plant}/value-defaults/values?field_key=` (`get_setup_value_default_values`) — authenticated, plant-guarded `{listed, observed}`: the plant priority-list keys and the distinct order values for that field, both in the client canonical form. 400 for a field not in the plant's definition (or no definition).
  - `DELETE /setup/{plant}/matrix` (`delete_setup_matrix_rows`) — deletes only selected cells (a sparse machine deletion exposes inherited plant truth).
  - `PUT /setup/{plant}/lines/{machine}/state` (`save_setup_line_state`) — authorized plant schedulers assert current physical machine state.
  - `PUT|GET /setup/{plant}/lines/{machine}/compatibility` (`save_setup_line_compatibility`/`get_setup_line_compatibility`) — admin-only per-machine setup-signature opt-out, distinct from the global `excl_optimizer` flag.
  - `POST|PUT|DELETE /setup/{plant}/overrides[/{id}]` (`create_setup_override`/`save_setup_override`/`clear_setup_override`) — one-off occurrence-specific adjustments.
  - Local helpers used only within this domain: `_setup_plant_guard`, `_setup_error` (409 for stale signature version, else 400), `_setup_freshness` (attaches `{signature_version, request_id}` to every response), `_setup_observed_at`.
- **`data.py`** (1,660 lines, originally a whole-file move of the former root `setup_data.py`) — plant-scoped, versioned persistence across five tables: `setup_definition`, `setup_matrix`, `machine_setup_state`, `setup_occurrence_override` and (2026-10-27) `setup_value_default`. Key functions: `canonical_state_key`/`derived_order_state_values`/`_normalise_value` (canonicalization — the server-side twin of `frontend/setup/setup-domain.mts`'s `normalizedValue`), `validate_setup_minutes`/`validate_override_minutes`/`validate_signature_version`/`validate_matrix_rows`, `set_definition_active`/`save_definition`, `replace_plant_matrix`/`upsert_machine_matrix_rows`/`delete_machine_matrix_rows`/`delete_plant_matrix_rows`, `save_value_defaults`/`value_defaults_values`/`canonical_default_value`, `set_machine_state`/`derive_machine_state_before_replacement`/`capture_setup_states_before_schedule_mutation`/`should_replace_machine_state` (the `derived`/`manual`/`actual` trust ordering), `upsert_occurrence_override`/`update_occurrence_override`/`clear_occurrence_override`, `get_setup_snapshot`/`current_signature_version`, `build_setup_coverage`/`get_setup_coverage`/`page_missing_pairs`/`page_matrix_rows`.

Both files' header docstrings confirm a **pure move from `brain.py`** (routes.py: lines 2517-2832 of the pre-split file, per `docs/architecture/domain-refactor-plan.md` §4) — route paths and payload/response shapes are byte-identical to before.

## Key invariants & hazards

- **Observation-only, always.** This module never changes an order's schedule — every write here is to setup truth (definitions, matrix minutes, machine state, overrides), never to `orders`. The scheduler (optimization domain) reads this data; nothing in `backend/setup/` writes a schedule.
- **`derived < manual < actual` trust ordering** (`data.py`'s `_SOURCE_TRUST = {"derived": 1, "manual": 2, "actual": 3}`) governs `should_replace_machine_state`: a lower-trust source observation never silently overwrites a higher-trust one already on file for `machine_setup_state`.
- **Writes are gated by the `setup_scheduler` role permission.** `auth.require_setup_scheduler` needs `roles.settings.permissions.setup_scheduler === true` **and** at least one `role_plants` row for the caller — see routes.py's `Depends(auth.require_setup_scheduler)` on the machine-state and occurrence-override write routes. Admin-gated routes (definition, matrix import/delete, compatibility) instead use `auth.require_admin`.
- **The activation story has moved, and the wider refactor's own planning materials are dated about it.** `PUT /setup/{plant}/active` (writing `setup_definition.active`, per-signature-version) is **vestigial but retained** — its own docstring says so verbatim: "no UI or optimizer gate reads `setup_definition.active` any more," kept only because removing it means also removing every caller/test, judged higher blast radius than leaving one unread write path in place. The **real** gate as of Workstream D2 (2026-08-20) is `plants.setup_active`, written through `PUT /plant/{plant}/setup-active` (`master_data.set_plant_setup_active`) and read through `GET /setup/{plant}`'s `plant_active` field (`master_data.get_plant_setup_active`). These are three independently inspectable gates, never conflated: `plants.setup_active` (this one), `machine.setup_compatible` (per-machine opt-out), and the frontend's own `setupSnapshot.plant` identity check.
- **Value defaults store the rule, not the rows (2026-10-27).** Table `setup_value_default` (`migrations/2026-10-27-1-setup-value-defaults.sql`, mirrored in `schema.sql`; additive, no ledger row), primary key `(plant, signature_version, field_key, value)`, `setup_min` 0-10,080. Not in `ALLOWED_TABLES`; no FK (plant deletion orphans them exactly like the four sibling setup tables). `get_setup_snapshot` returns `value_defaults: [{field_key, value, setup_min, signature_version, updated_by, updated_at}]` for the current version inside its REPEATABLE READ transaction (`[]` when no definition). **Canonical value:** the stored key is the **client** form (`canonical_default_value`: trimmed; lowercase for the literals "true"/"false"; else uppercase), because `_normalise_value` upper-folds a *string* "true" to "TRUE" while the client keeps it lowercase; every server value that meets a default (state values, stored matrix rows, `distinct_order_values`) goes through this helper first. **Carry-forward:** in `save_definition`'s bump branch every default whose `field_key` is still in the new `fields` is copied to the new version (`INSERT ... SELECT ... ON CONFLICT DO NOTHING`); a `strict_blanks`-only change also bumps and copies everything; a removed field's defaults stay on the old version and are ignored; matrix rows keep the reset. Matrix import/export/plant replace ignore defaults.
- **Coverage is default-aware and counted in Python (2026-10-27).** `_coverage_pair` (pure path) gains the tier and reports `covered_by` (`row`/`implicit_zero`/`value_default`/null). The server counts (`_coverage_counts`) no longer run SQL over an effective-rows CTE: states per machine come from observed orders, one plant-wide text row fetch (`_fetch_matrix_rows`, bounded to rows whose from and to keys are both in the observed state universe) feeds int-encoded per-machine pair sets built transiently (never retained per machine), and default coverage uses exact grouping maths with no pair enumeration: for a to-state b, D(b) is the fields whose b-value has a default, and a pair (a, b) is NOT default-covered iff a agrees with b on every field in D(b); states are grouped by projection per D-mask (at most 2^fields masks, 16 on a legacy four-field definition), then recorded rows that are also default-covered are subtracted. The reachable missing page is a lazy **to-state-major** generator (`_iter_missing_pairs`; whole machines and whole to-states are skipped by their missing counts to honour `offset`); `_page_reachable_missing_pairs` is kept as its entry point (the old row-major window scan and `_COVERAGE_SCAN_SIZE` are gone) and `missing-pairs.csv` reuses the page. The observed kind applies the tier per observed pair in Python (its SQL window is lifted and the page cut afterwards only when any default exists). A brute-force oracle test pins the grouping maths. **Performance (measured on the dev box):** a whole missing-pairs request on a typical 70-machine, 50k-row plant takes ~0.8 s, **above the spec's 500 ms target**; a stress case where all machines share one 1,024-state universe takes ~6.5 s and ~130 MB. Follow-up if it matters: cache the counts per (plant, version, matrix token, defaults) instead of recomputing per request.
- **Stale-write conflicts are 409, not 400.** `_setup_error()` inspects the exception message for "is stale" (case-insensitive) to distinguish a real optimistic-concurrency conflict (stale signature version, or a stale plant matrix token) from an ordinary malformed-request 400 — every mutating route funnels its `ValueError` through this helper.
- **`data.py` is also consumed outside `backend/setup/`:** `backend/integration/routes.py`, `backend/integration/sap_sync.py` and `backend/distribution/data.py` call `setup_data.capture_setup_states_before_schedule_mutation(...)` before an ingest/SAP-sync/distribution run overwrites schedules — capturing a `derived` machine-state snapshot from what's about to be replaced. This is a real cross-domain dependency (integration → setup), not a coupling bug.

## Plant-default matrix replace: required, content-complete `plant_matrix_token`

- `POST /setup/{plant}/matrix/import` (`data.replace_plant_matrix`) is delete-then-insert, so it **requires** the `plant_matrix_token` the caller read from `GET /setup/{plant}` (`get_setup_snapshot`). A missing token is a `ValueError("A plant matrix token is required ...")` (400); a token that no longer matches the live rows -- checked under the definition row lock, before any delete -- is `"... is stale: another admin changed it; reload and retry"` and maps to **409** in `routes._setup_error`.
- The token (`data.plant_matrix_token`) is an md5 over every replaced column of the plant-default scope (`machine = ''`), ordered by `from_key, to_key`: `from_key`, `to_key`, `setup_min`, `source`, **`source_metadata`**, `source_reference`. Each field is **length-prefixed** and a NULL is encoded distinctly from `''`, so adjacent values can never blur (`'a,'+'b'` vs `'a'+',b'`) and a metadata-only or NULL-to-empty edit by another admin invalidates a stale replace. Adding a column to the replaced set means adding it to `_MATRIX_TOKEN_FIELDS`. No schema change; the empty scope hashes to `md5('')`.
