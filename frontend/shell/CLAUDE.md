# Shell — boot, login, top-level routing, and the root-pinned classic scripts

## What lives here

- **`application-shell.mts`** (2686 lines) — `export { Settings, SessionUIAdapter, showLoginScreen, EmptyState, PlantSelector, App }`.
  - `Settings` — personalization/workflow defaults catalog; lives here (not one of the 14 tracked CQ-1 modules) because `SessionUIAdapter` is its only real reader.
  - `SessionUIAdapter` — session/login UI glue. The Sign out button calls `Session.signOut({hasPendingWork, beforeClear})`: confirms if there is unsaved work, halts cache writes, clears local planner data, reloads. The login screen distinguishes unreachable / throttled (429) / unavailable (5xx) / invalid-credentials.
  - `showLoginScreen` — renders the login gate.
  - `EmptyState` — no-plant/no-data placeholder screen.
  - `PlantSelector` — plant picker.
  - `App` — top-level tab switching and screen lifecycle. The Gantt tab has three sub-views driven by `App._GANTT_SUBS` (`timeline`, `orders`, `distribution` — pane id, label key, scroll key per entry; Distribution mounts `DistributionPane` from `frontend/distribution/`). `App._trackDirty` (Store subscriber) maintains `Persistence._dirtyIds`/`_forceIds`/`_firmDirtyIds`: `refresh`/`note`/`distribution`-sourced events are never dirty; `engine`/`undo` writes are force-saved; a firm change marks `_firmDirtyIds` (the save sends the manual firm only for those ids) and a `tasks:bulk` load clears all three. Plant switches go through `Persistence.confirmPlantSwitch`. `App._bootMain`/`_domReadyGate` are deliberately **not** defined here — they stay in `app.js` and are assigned onto this same exported `App` object from `app.js` after this module loads (a documented, intentional asymmetry — see the file's own header, lines 9-20).
- **`tab-resolvers.mts`** (28 lines) — the `ActiveTabResolvers` seam (`setActiveTabResolvers`/`getActiveTabResolvers`, plus the `ActiveTabResolvers` type: `currentTab()`, `currentMasterSub()`, `laborSub()`). Extracted verbatim from the old `plant-and-administration.mts` in Phase P2 so `master-data/admin-ui.mts`'s `Plant` and `labor/labor-planning.mts`'s `LaborPlanning` can each ask "am I currently the visible tab?" without a bare reference to `App`. Defaults are no-op closures returning `null`, so a call before boot wiring never throws.

**Also the custodian of the root-pinned classic scripts that never moved into any domain folder:**
- `frontend/app.js` (797 lines) — boot orchestration, DI-seam wiring, the CQ-1 bridge destructure, and a compatibility `return {...}` namespace. Holds no module bodies.
- `frontend/app-entry.mjs` — the real module loader (see Integration points below for its current import list).
- `frontend/nimbus-intelligence.js` (2613 lines) — the intelligence layer, loaded after `app.js`: `CommandPalette` (Cmd+K), `NeedsEngine`, `TimeMachine`, `Confidence`, `RipplePreview`, `Diff`, `Patterns`, `DarkMode`, `LangSwitcher`, `IntelDB`. Deliberately stays a classic (non-module) script — it needs `NIMBUS` as a bare identifier via shared lexical scope, and now uses `Store` event subscriptions rather than runtime monkey-patches (none remain).
- **Preference writes (2026-10-28).** `Session.setPref` is optimistic with a 600 ms debounce; flushes are serialized (one PATCH on the wire, newer edits queue behind it and a stale response never rolls them back), revert is first-writer-wins per key, and `Session.flushPrefs()` resolves a boolean (false = a batch failed and was reverted, toast already shown). A failed save emits `settings:change` with source `settings-pref-revert`; `SessionUIAdapter._onPrefRevert` then calls `DarkMode.reapply()` (body class, pill, offline cache) and re-renders the open Settings panes. `LangSwitcher.set` reloads only when the flush succeeded and writes `nimbus.locale` only then. Optimizer strategies and seedable presets live in ONE place, `frontend/optimization/optimizer-prefs.mts`, used by both the Optimize dialog and the Settings Workflow pane. `session:changed`/`refresh` re-applies theme and first day of week; language is applies-on-next-boot. `landingView.sub` must be a sub-view the landing picker offers for that tab, else the tab default is used.
- `frontend/index.html` (3125 lines) — script/style load order, `NIMBUS_BUILD_ID`, the CDN SRI hashes (CSP is a report-only response header from `brain.py`, not a tag).
- `frontend/styles.css`, `frontend/locales/` — design tokens and i18n string maps.

## Counterpart

None — this is a frontend-only shell/boot domain.

## Key invariants & hazards

- **`NIMBUS_BUILD_ID` is the single cache-bust source.** Set at `index.html:50` (`window.NIMBUS_BUILD_ID = '2026-09-18-2'`) and read again at `index.html:3103`. It drives every `?v=` query param, `Config.BUILD_ID` (in `platform/foundation.mts`), and `app-entry.mjs`'s `runCacheBustGuard()`. There is no separate `APP_VERSION` constant. The hand-set value in `index.html` (plus `styles.css?v=`) is the local-dev fallback; the Dockerfile's `frontendbuild` stage overwrites both with the git SHA when built with `--build-arg BUILD_ID=$(git rev-parse --short HEAD)`, so deploys no longer need a manual bump.
- **`runCacheBustGuard(win)`** (`app-entry.mjs`, lines ~132-145): compares `sessionStorage['nimbus.app.ver']` to `window.NIMBUS_BUILD_ID`; on mismatch, stores the new version and `location.replace(...)`s with a refreshed `_v=` param (stripping any prior one). Wrapped in try/catch so storage/location failures never block boot. It was deliberately moved to the top of `app-entry.mjs` (rather than the top of `app.js`, where it lived pre-refactor) so it fires before the deferred-module load even starts, recovering most of the redirect-timing gap the new load order introduced.
- **Script/module load order matters.** `app-entry.mjs` (a `<script type="module">`) imports the real ES modules, bridges their exports onto `window.__NIMBUS_*` globals, then injects `app.js` and `nimbus-intelligence.js` as classic scripts in that order, then deletes all the bridge globals (`app-entry.mjs` lines ~99-106) since `app.js` only reads them synchronously at its own IIFE top and `nimbus-intelligence.js` never reads them at all. Locale files load before all of this (first in the script chain) because `app.js` reads them when defining `window.t`.
- **Classic-script constraints.** `nimbus-intelligence.js` must stay non-module for the bare-`NIMBUS`-identifier reason above — don't convert it to an ES module without re-solving that coupling.
- **Tab-scoped chrome + drawer sub-navigation (2026-09-09).** `App.goto` writes `document.body.dataset.tab`; CSS keys on it to show the scheduling-only action cluster `#context-sched-actions` (Optimize/What-If/Print) in the context bar. Hour/Day/Week + Fit/Now sit at the right end of `#gantt-filterbar` inside the Timeline pane (so they hide with the pane on the Orders sub-view — no per-id display toggling remains in `gotoGanttSub`). There is no other per-tab show/hide mechanism for shared chrome — reuse the attribute rather than inventing another. The Gantt Timeline/Orders/Order Distribution switch lives in the nav drawer as `.nav-sub-btn[data-gantt-sub]` children under the gantt `.tab-btn` (wrapped in `.nav-group`, with a `#nav-gantt-chevron` collapse toggle). Children deliberately carry **no** `.tab-btn`/`data-tab` so the generic tab wiring, `goto`'s active-toggle, and `SessionUIAdapter._applyGates` ignore them; `_applyGates` hides the whole `.nav-group` with the parent. `_setGanttNavExpanded` also toggles `.open` on `#nav-group-gantt`, which is the CSS hook that turns the active parent into a header-style row so only the active child carries the selection marker. Zoom buttons are found via `#gantt-zoom-controls .seg-btn[data-view]` (three sites: `App.init`, `Timeline.setView`, `Timeline.gotoLineDay`). The What-If button must stay `.sandbox-btn` with a flat text node — `SandboxAdapter` rewrites its `textContent`.
- **i18n routing.** Route all new/changed UI text through `data-i18n`/`t()`, even tiny badges, rather than hardcoding to match a pre-existing hardcoded neighbor — `tests/modules/locale-completeness.test.mjs` pins coverage.
- **Flatpickr standard.** All date and time inputs use [Flatpickr](https://flatpickr.js.org/) — never native `<input type="date">`, `datetime-local`, or `time`. Flatpickr loads via CDN in `index.html` (before `styles.css`). The NIMBUS amber theme lives mid-`styles.css` under `/* Flatpickr calendar — NIMBUS amber theme */`, with dark-mode counterparts later in the file. **Exception:** the AG Grid inline `start_date` cell editor (`Table._DateTimeEditor`) is a native `datetime-local`.

  | Type | `enableTime` | `noCalendar` | `dateFormat` | `altInput` | `altFormat` |
  |------|:---:|:---:|---|:---:|---|
  | Date-only | — | — | `"Y-m-d"` | `true` | `Util._dateFormatPref()` (default `"m/d/Y"`) |
  | Datetime | `true` | — | `"Y-m-d\\TH:i"` | `true` | `Util._dateFormatPref()` + `Util._fpTimeAltFormat()` |
  | Time-only (hours table) | `true` | `true` | `"H:i"` | — | — |

  Modal pickers are **module-level, lazily initialized, and conventionally named `_fp*`** — built once behind an `if (!Module._fpX)` guard, then `Module._fpX.setDate(d, false)` (`false` suppresses `onChange`); table time inputs are built inline per row. `grep -n "flatpickr(" frontend/*.mjs` finds every instance. With `altInput: true`, existing `.value` reads keep working: the hidden original input holds the `dateFormat` value, the visible alt input shows `altFormat`.
- **CSP is REPORT-ONLY (#28).** `brain.py`'s `csp_report_only_mw` adds `Content-Security-Policy-Report-Only` to `text/html` responses only (policy in `_CSP_REPORT_ONLY`: `script-src` is `'self'` + the pinned CDN origins unpkg.com and cdn.jsdelivr.net, `style-src` adds `'unsafe-inline'` + Google Fonts, `connect-src 'self'`, `worker-src 'self' blob:`, `frame-ancestors 'none'`). Nothing is blocked. Violations POST to `/logs/csp-report` (`backend/admin_ops/routes.py`, tolerant, always 204, reads <= 8 KB, `brain.py` rejects a `Content-Length` over 16 KB with 413; repeats are de-duplicated and rate-limited so the report-only stream cannot evict real errors from the log ring) and land in the backend log ring as category `csp` / event `csp.report` - read them in the Admin log viewer. Expect reports for the ~108 static inline `on*=` handlers and the `document.write` bootstrap at the bottom of `index.html`; `script-src` deliberately omits `'unsafe-inline'` so that stream is the honest work list. **Enforcing requires**: (1) converting every inline `on*=` attribute to `addEventListener` wiring, (2) replacing the `document.write` script loader with DOM-created script elements (or nonces), (3) moving the two inline `<script>` blocks to files or adding hashes/nonces, (4) a clean report window in production, then renaming the header to `Content-Security-Policy`. A CDN version bump keeps working (origin-level allowlist) but still needs its SRI hash recomputed. CDN assets are also covered by Subresource Integrity (`integrity=` + `crossorigin="anonymous"`), except the Google Fonts stylesheet (content varies by user agent, so it cannot take SRI).

- **The `alerts` tab mirror list (Alert Monitor, 2026-10-20).** A top-level tab is mirrored in many places, and adding one means touching every one: the `TopLevelTab` union (`platform/types.mts`); `Session.DEFAULT_PAGE_ACCESS` (`security/session.mts`, `alerts: true`); the Roles "Page Access" list in `security/security-admin.mts` (its order must match the shell's and `DEFAULT_PAGE_ACCESS`'s key set); `SessionUIAdapter._landingTabDefs()` (the landing-tab dropdown); `App._firstAccessibleTab`'s order (`home, gantt, labor, alerts, masterdata, admin`); the tab-title `KEY` map; the `data-tab="alerts"` button and `#alerts-tab` panel in `index.html`; the scroll-memory switch (`'alerts'` maps to `#am-scroll`); `App.goto`'s leave hook (`AlertMonitorPane.setActive(false)`) and enter branch (`init()`, `render()`, `_restoreScroll('alerts')`); the deep-link `validTabs` list; and `tab.alerts` in all five locales. `AlertProfileMatches.init()` is called from `App.init`, not from the tab: the producer must run while the Gantt tab is open.
- **Alert Monitor settings keys** (`Settings.CATALOG`, category workflow, tier user, not region-scoped, written with `Session.setPref`, read with `Store.pref`): `alertProfileByPlant` (object, `{plant: profileId}`, the whole map is read-modified-written as one key), `alertProfileGanttHighlight` (boolean, default true), `alertMonitorView` (object; `'*': {view, lens}` is the page-wide Inbox | Matrix choice since 2026-10-30, older per-profile `groupBy`/sort entries only migrate the lens), `alertsShowAcknowledged` (boolean, default false), `alertMonitorOverview` (retired, no longer read; enum, default `open`; `collapsed` folds the Overview band). The User Settings modal renders the profile picker and Gantt-highlight rows through `SessionUIAdapter._alertProfileRowsHtml` / `_initAlertProfileRows`: a searchable combobox (`.us-combo*`; a stored id that no longer exists reads as "All alerts" and is left in place until the user picks) plus a "Manage profiles" button that closes the modal and calls `App.goto('alerts')`. **The profile editor is never opened from settings** (a modal stacked on the settings modal would fight the focus trap); Manage and Create live on the Alert Monitor page.

## Gotchas

- The root `CLAUDE.md`'s description of `app-entry.mjs`'s import list is stale (pre-P2/P3/P4 module names) — use the list above, verified against the live file.
- `App._bootMain`/`_domReadyGate` living in `app.js` rather than `application-shell.mts` is deliberate, not an oversight — don't "fix" it by moving them without re-reading the header comment's rationale.
- `Settings` living in `application-shell.mts` looks like it could belong to a settings/preferences domain, but it's here on purpose (single reader: `SessionUIAdapter`).
- **Alert recompute triggers (2026-10-22).** `App.init`'s "Keep alerts + dashboard in sync" subscriber calls `Alerts.scheduleRecompute()` on `task:update`, `tasks:bulk`, `tasks:bulkUpdate`, `firmed:change`, `calendar:change`, `blocks:change`, `plantBlocks:change`, and now also `setup-snapshot:replace`, `lineSettings:change` and `master-data-changed` (setup/line-buffer/plant-row edits previously left alerts stale). The recompute is debounced; `Timeline._onStore` also schedules a coalesced rebuild on `master-data-changed`.

- **New-version watcher (2026-10-28).** `version-watch.mts` (started from `App.init`, beside the `visibilitychange` handler) polls `GET /version` every 5 min while the tab is visible and on return to visible, compares it with `window.NIMBUS_BUILD_ID`, and calls the injected `onNewVersion` presenter; it uses plain `fetch` and swallows every error, and never reloads by itself. `makeUpdatePresenter` drives the static `#update-banner` strip in `index.html` (a 34px info-tint in-flow strip under the context bar; `body.update-available` steps the fixed-top siblings down): deduped per remote id, Dismiss lasts until a newer id arrives, it never steals focus, and Refresh goes through `Persistence.hasPendingWork()` + `Modal.confirm` before `location.reload()`. The shell injects `onLayoutChange` to redraw the Gantt after the strip toggles; no new locale keys (`toast.update_*`, `btn.dismiss`). `index.html` itself is served `Cache-Control: no-cache` (`brain.py` `static_mjs_no_cache_mw`) so a normal refresh revalidates it.
- **Return-to-foreground calendar probe (2026-10-23).** `App.init`'s `visibilitychange` handler, on becoming visible, also calls `Persistence.refreshHorizonsOnReturn()` (the same 10 s-throttled `/tasks/horizons` probe a Gantt entry runs) and schedules a Timeline rebuild only when it changed the horizon bands and the Gantt timeline is showing. `App.init` also wires `Persistence._calendarRefreshBlocked = () => !!Interaction._isDragging`, so a calendar re-hydration never lands mid-drag.
- **Format prefs reach existing pickers (settings audit Wave D, 2026-10-28).** `SessionUIAdapter._repaintDisplayFormat` (time/date format change) and `App._applyFirstDayOfWeek` (week start; also run on a failed-save revert and a session refresh) both end in `Util.refreshFlatpickrPrefs()`, so pickers built before the change update their altFormat and week start live; only the popup 24-hour clock waits for the next built picker. Labor Plan week columns are ISO weeks (Monday start, the stored period keys) whatever `firstDayOfWeek` says; the pane hint says so. The `Settings` catalog has no `timezone` key any more. `Settings.isRegion/byCategory` and the `type/tier/region` fields are still unread by the app but are pinned by `tests/modules/application-shell.test.mjs`, so they were left.
