# Distribution — SAP aggregate work center ↔ NIMBUS per-machine sub-order split UI

## What lives here

- **`distribution-pane.mts`** — `DistributionPane`, the Scheduling Board's Order Distribution sub-tab (§6). Structural shape mirrors `frontend/setup/setup-admin.mts`/`frontend/labor/labor-planning.mts`: a plain object literal with `init()` (wires the static shell + Store subscriptions once, called from `application-shell.mts`'s `gotoGanttSub`) and `render()` (fetch + redraw, called every time the Gantt sub switches to `'distribution'`). Also exports a set of pure, DOM-free functions used by both the pane and its tests: `pickPrimaryBadge` (§6's severity-ordered badge choice), `formatBadgeCount` (nav-badge cap/hide-at-zero), `toPersistedFilters`/`fromPersistedFilters` (the `batch`-excluded persistence round-trip), `selectEmptyState`/`filtersAreActive`, `formatSubOrders`, `describeDefaultBasis`, `reviewedCheckboxState`.
- **`shares-editor.mts`** (P2-16) — the shares editor's pure, DOM-free logic: weight math (`onlyThisMachine`/`evenWeights`/`quantityToWeight`/`resolvedWeight`/`buildSharesPayload`/`weightsSignature`), merging a dry-run response onto the editor's row state (`mergeRowsWithDryRun`/`computeTotals`), the Save-button disabled-until-settled state machine (`computeSaveButtonState`), removal-confirm gating (`needsRemovalConfirm`/`sortRemovedFrozenFirst`), the Undo-disabled-after-`base_version`-moved check (`isUndoDisabled`/`previousSharesToWeightMap`), and error-code-to-locale-key mapping (`distErrorLocaleKey`). Kept as its own module rather than folded into `distribution-pane.mts` because it is the most logic-heavy piece of the whole feature; every export is independently unit-tested with mocked dry-run fixtures, no DOM/fetch.

**Shipped (P2-15):** the pane shell + shell/nav registration (`_GANTT_SUBS` entry, the third `nav-sub-btn`, the `#context-sched-actions` CSS hide rule, the nav-badge reading `Store.distributionSummary.needs_review`), the paged list (`GET /distribution/{plant}`) with search/work-center/bucket/date-horizon/batch filters (machines is a read of the shared `Store.selectedLines`, not a second picker — §6's own wording), the §6 status-badge severity table (one primary `.sap-pill` per row + a `+{{n}}` tooltip for the rest), and the detail panel's **static header** display (SAP order/material/work center/quantity/window/Σ hours/the "why these defaults" sentence/updated-by/reviewed-by). The list's Reviewed checkbox and its two simplest badge actions (`needs_review` → mark reviewed, `qty_changed` indeterminate → re-stamp `reviewed_quantity`) call `POST /distribution/{plant}/review` directly — both are simple, single-call actions, not the editor. **Truncated-list notice (D13):** the server caps the list at the oldest 5,000 orders; when a response's `meta.truncated` comes back `true`, a `.dist-list-truncated-notice` line ("Showing the oldest 5,000 orders — narrow the filters to see the rest.", `ui.dist_list_truncated`) appears above the grid, cleared on the next successful (non-truncated) fetch and also cleared if a fetch fails outright so a stale notice never lingers over a now-empty or errored list. "Refresh" keeps every page already loaded, not just the first.

**Shipped (P2-16):** the shares editor body (replaces `#dist-shares-editor-placeholder`) — one row per current share (including 0-weight/purged, greyed, "(no sub-order)"), a TOTAL row, per-row **Only this machine**/**By quantity** toggle (D35: the typed target quantity converts to a RELATIVE weight solved against the other rows' current weight total and the header's total order quantity, not a naive 1:1 copy — a quantity at or above the header total, or every other row already explicitly zeroed, converts to the same weight map **Only this machine** uses instead of dividing by zero; a header with no, or a non-positive, `order_quantity` has no usable total to divide by at all, so the conversion is skipped entirely and the row's weight is left unchanged rather than silently collapsing to "only this machine") and a header-level **Even** button, all backed by `shares-editor.mts`. A 300ms-debounced dry run (`POST .../shares` with `dry_run: true`) drives Effective %/Qty after/Hours after/Outcome per row. **Preview identity:** each dry run is keyed to the selected header object AND its own sequence number, both bumped on every input/selection change — a response that lands after the planner moved to a different order, re-opened the same order fresh, or typed again is recognized as stale and dropped, so a late preview for order X can never settle onto order Y's editor (or an earlier version of X's). **Save** is disabled until a dry run for the CURRENT inputs has settled, labels the removal count, and — when the settled preview shows removals — opens `Modal.confirm({tone:'danger'})` (frozen-first) before posting with `confirm_remove_scheduled: true`; a 409 `children_scheduled` race re-shows the same confirm with fresh data, a 409 `stale` refetches the header and toasts. **Write latch (D44):** Save/Reset/Undo/Repair all run through one shared `_writeBusy` latch — it disables the write buttons synchronously (before the click handler's own first `await`), so a second click landing before the first request even leaves the browser is a silent no-op rather than a second in-flight write; the latch always clears and the detail panel always re-renders once the write settles, success or failure. A successful write patches `children`/`removed` into `Store` directly (`Store.tasks[id]` mutate-in-place for existing children, direct insert + `Store.rebuildPlantIndex()`/`tasks:bulkUpdate` emit for brand-new ones, `Store.removeTask` for removed ones) — no plant reload — then calls `Engine.reconcileRuntimeSchedules(plant)` and shows an inline `.dist-banner` (not a toast) with **Save schedule** (`Persistence.saveAll()`) / **Undo** when any kept child's bar resized, listing firmed ones (see the gap note below — the current `reconcileRuntimeSchedules` does NOT actually skip firmed tasks, contrary to this feature's own design doc). **Reset to work-center defaults** and **Undo last change** share the SAME dry-run/confirm/write pipeline (`_runWritePipeline`/`_postDistWrite`/`_confirmRemoval`/`_finishWrite`) rather than duplicating it. The detail panel's own **Reviewed** checkbox (including the indeterminate re-stamp) and **Show on Gantt**/**Open in Inspector** (via the ambient `NIMBUS.Selection`/`NIMBUS.Timeline.focus`, added to `frontend/types/nimbus-global.d.mts`) are wired. **Bulk actions** on the list's checked rows — **Mark {{n}} reviewed** / **Reset** — post `orders:[...]`, with any per-item 409/error listed in a `Modal.confirm` detail. **What-If guard**: `Sandbox.active` disables Save/Reviewed/Reset/Undo/bulk actions with hint `ui.dist_whatif_blocked`. Every OTHER status's list badge now has a real one-click action too: `incomplete` → Repair (re-posts the header's current stored shares unchanged), `runtime_mismatch` → `Persistence.saveAll()`, `separation_violated` → opens the detail then Show-on-Gantt; every multi-choice status (`mode_mismatch`/`wc_changed`/`membership_changed`/`below_min_lot`/`zero_quantity_children`) opens the detail panel, where the choice is made; `purged` stays a no-op per §6's own table.

**Known gap (documented, not fixed here):** aggregate_to_detail.md §6 says "`reconcileRuntimeSchedules` skips firmed tasks... the pane says so," attributing that to `persistence.mts:799`. The actual function (`frontend/optimization/engine.mts`'s `reconcileRuntimeSchedules`) has no firmed check at all — its own doc comment states "Firmed is parent-level only and does not suppress this required runtime correction." `distribution-pane.mts` calls it directly (verified safe: it takes a bare plant string and brackets its own Calendar run) and still surfaces firmed status on any resized child in the banner, but the underlying premise that firmed children are excluded from this pass is doc drift in aggregate_to_detail.md, not current behavior — don't "fix" the pane to skip firmed children to match the stale doc without re-verifying `reconcileRuntimeSchedules` first.

**Deferred/skipped, with reasons:**
- **Deep-link routing** (`#gantt/distribution?batch=<id>&order=&material=`, `?bucket=needs_review` auto-selecting a row/filter) — not wired. `App.gotoGanttSub`/`_GANTT_SUBS` don't currently pass extra params through to a sub-pane's `render()`, and extending that shell mechanism cleanly was judged non-trivial for this task's scope (root `CLAUDE.md`'s cross-domain-reach convention would need a real signature change in `application-shell.mts`, outside `frontend/distribution/`) — left for a follow-up task rather than reworked here.
- **Editor virtualization** (§6: a `VirtualList` once a header has more than ~12 shares) and the optional stacked-bar visualization are not implemented — the editor renders a plain table regardless of row count. Fine at the pilot's actual work-center sizes; a real gap at the Production Scale Roadmap's target scale.
- **A work-center member with literally no share row yet** (freshly joined, no planner has weighted it) does not appear as an editable row — the editor's row set is `GET .../{order}/{material}`'s `shares[]` (every share the header already knows about, including 0-weight/purged), not the work center's live membership list, which would need an additional per-plant members lookup this task did not add.

**The Work Centers admin tab (§4.3, P1) is NOT in this folder** — that work landed as `WorkCenters` inside `frontend/master-data/admin-ui.mts` (`PUT /distribution/{plant}/workcenters/{wc}`'s frontend counterpart). It no longer creates work centers (creation lives with SAP sync ingest and the Manage Data grid instead); it autosaves behind a client-side pre-flight gate rather than staged Save/Discard; a zero-member work center is an unsaveable dead end by backend design, accepted not a bug. This folder is the Scheduling Board Distribution tab only.

## A real backend-shape correction worth knowing before touching this file

`aggregate_to_detail.md` §6's prose says the machine→work-center map comes from "`Store.masterData.workcenters`" and that `NimbusMasterLine` gains `sap_workcenter`/`distribution_weight` — that's still not quite what shipped for the machine→work-center map itself: only `NimbusLineSetting` (`Store.lineSettings[machine]`) gained `sapWorkcenter`/`distributionWeight`, not `NimbusMasterLine`. But `Store.masterData.workcenters` itself now DOES exist (added for the Alerts/optimizer-facing copy of work-center fields — `WorkCenters` in `master-data/admin-ui.mts` patches it alongside its own `_rows`/`_machines` on every save so Alerts recomputes against the saved values, and `setup-scheduler.mts`/`persistence.mts` read it too), and it is per-plant: `Persistence.load()` fetches `GET /master-data/sap_workcenter?plant=` for the selected plant only and sets `Store.masterData.workcenters` to that plant's rows, same as `plants`/`lines`. `distribution-pane.mts` still does NOT read that Store field — it keeps its own separate module-local `_workcenters` cache (`_loadWorkcentersIfNeeded`), fetched straight from the same `GET /master-data/sap_workcenter?plant=` endpoint and re-fetched on every plant switch, with its own stale-response guard (a response for a plant the user already left is dropped, success or failure, rather than wrongly marking that old plant "loaded"). That's a deliberate, independently-scoped read, not a bug — don't "consolidate" it onto `Store.masterData.workcenters` without checking `_loadWorkcentersIfNeeded`'s own stale-guard comment first.

## Integration points

**Write safety (2026-10-01):** all shares/reset/undo/bulk-reset/repair requests require affected local schedule edits to be resolved first. A submitted write captures the affected group's persistence baselines; newer edits retain the whole group with old tokens and unresolved conflict flags. This prevents later ordinary or atomic saves from silently combining a server version with unsubmitted attributes. Responses for a different plant never hydrate its Store; detail refresh and Undo/banner state are scoped to the selected order. Regression tests exercise the actual private handlers through a test-only transpiled wrapper.

**Imports in:** `../platform/foundation.mjs` (`Config`, `Util`, `ErrorLog`, `Toast`, `Modal`), `../platform/store.mjs` (`Store`, `UndoStack`), `../security/session.mjs` (`Session` — `isAdmin()` gates the empty state's "Open Work Centers" button, `setPref()` persists filter state), `../insights/services.mjs` (`loadDistributionSummary`, called after a review write so the nav badge/Dashboard/Ctrl+K counts refresh immediately), `./shares-editor.mjs` (the P2-16 pure logic module). **P2-16 additions, real cross-domain imports** (verified one-directional — grep confirms nothing in `optimization/`/`scheduling/` imports `distribution/` back, so these are plain edges, not new cycles): `../optimization/sandbox.mjs` (`Sandbox`, the What-If guard), `../optimization/engine.mjs` (`Engine`, for `reconcileRuntimeSchedules`), `../scheduling/persistence.mjs` (`Persistence`, for `saveAll()`). Reaches shell navigation (`App.goto`/`App.gotoMasterSub`), `EmptyState.render`, and (P2-16) `Selection.set`/`Timeline.focus` for Show-on-Gantt/Open-in-Inspector, through the ambient `NIMBUS` global (`frontend/types/nimbus-global.d.mts`), the same idiom `frontend/master-data/material-grids.mts` uses — NOT a real import, since this is a leaf pane and shell already imports it downward (see next line).

**Imported by:** `frontend/shell/application-shell.mts` imports `DistributionPane` directly (the same way it already imports `Table`/`Timeline`/`WorkCenters`) and calls `.init()`/`.render()`/`.setActive()` from `App.gotoGanttSub`'s `'distribution'` branch.

**Endpoints called:** `GET /distribution/{plant}` (list, paged 50), `GET /distribution/{plant}/{order}/{material}` (detail), `POST /distribution/{plant}/review` (single-header and bulk), `POST /distribution/{plant}/{order}/{material}/shares` (dry-run preview and real write — Save/Undo/Repair), `POST /distribution/{plant}/reset` (dry-run preview and real write, single-item and bulk `orders[]` — Reset), `GET /master-data/sap_workcenter?plant=` (work-center combobox source + the "has a distribute-mode work center" empty-state check).
