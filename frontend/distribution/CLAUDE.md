# Distribution — SAP aggregate work center ↔ NIMBUS per-machine sub-order split UI

## What lives here

- **`distribution-pane.mts`** — `DistributionPane`, the Scheduling Board's Order Distribution sub-tab (§6). Structural shape mirrors `frontend/setup/setup-admin.mts`/`frontend/labor/labor-planning.mts`: a plain object literal with `init()` (wires the static shell + Store subscriptions once, called from `application-shell.mts`'s `gotoGanttSub`) and `render()` (fetch + redraw, called every time the Gantt sub switches to `'distribution'`). Also exports a set of pure, DOM-free functions used by both the pane and its tests: `pickPrimaryBadge` (§6's severity-ordered badge choice), `formatBadgeCount` (nav-badge cap/hide-at-zero), `toPersistedFilters`/`fromPersistedFilters` (the `batch`-excluded persistence round-trip), `selectEmptyState`/`filtersAreActive`, `formatSubOrders`, `describeDefaultBasis`, `reviewedCheckboxState`.
- **`shares-editor.mts`** (P2-16) — the shares editor's pure, DOM-free logic: weight math (`onlyThisMachine`/`evenWeights`/`quantityToWeight`/`resolvedWeight`/`buildSharesPayload`/`weightsSignature`), merging a dry-run response onto the editor's row state (`mergeRowsWithDryRun`/`computeTotals`), the Save-button disabled-until-settled state machine (`computeSaveButtonState`), removal-confirm gating (`needsRemovalConfirm`/`sortRemovedFrozenFirst`), the Undo-disabled-after-`base_version`-moved check (`isUndoDisabled`/`previousSharesToWeightMap`), and error-code-to-locale-key mapping (`distErrorLocaleKey`). Kept as its own module rather than folded into `distribution-pane.mts` because it is the most logic-heavy piece of the whole feature; every export is independently unit-tested with mocked dry-run fixtures, no DOM/fetch.

**Shipped (P2-15):** the pane shell + shell/nav registration (`_GANTT_SUBS` entry, the third `nav-sub-btn`, the `#context-sched-actions` CSS hide rule, the nav-badge reading `Store.distributionSummary.needs_review`), the paged list (`GET /distribution/{plant}`) with search/work-center/bucket/date-horizon/batch filters (machines is a read of the shared `Store.selectedLines`, not a second picker — §6's own wording), the §6 status-badge severity table (one primary `.sap-pill` per row + a `+{{n}}` tooltip for the rest), and the detail panel's **static header** display (SAP order/material/work center/quantity/window/Σ hours/the "why these defaults" sentence/updated-by/reviewed-by). The list's Reviewed checkbox and its two simplest badge actions (`needs_review` → mark reviewed, `qty_changed` indeterminate → re-stamp `reviewed_quantity`) call `POST /distribution/{plant}/review` directly — both are simple, single-call actions, not the editor.

**Shipped (P2-16):** the shares editor body (replaces `#dist-shares-editor-placeholder`) — one row per current share (including 0-weight/purged, greyed, "(no sub-order)"), a TOTAL row, per-row **Only this machine**/**By quantity** toggle and a header-level **Even** button, all backed by `shares-editor.mts`. A 300ms-debounced dry run (`POST .../shares` with `dry_run: true`) drives Effective %/Qty after/Hours after/Outcome per row. **Save** is disabled until a dry run for the CURRENT inputs has settled, labels the removal count, and — when the settled preview shows removals — opens `Modal.confirm({tone:'danger'})` (frozen-first) before posting with `confirm_remove_scheduled: true`; a 409 `children_scheduled` race re-shows the same confirm with fresh data, a 409 `stale` refetches the header and toasts. A successful write patches `children`/`removed` into `Store` directly (`Store.tasks[id]` mutate-in-place for existing children, direct insert + `Store.rebuildPlantIndex()`/`tasks:bulkUpdate` emit for brand-new ones, `Store.removeTask` for removed ones) — no plant reload — then calls `Engine.reconcileRuntimeSchedules(plant)` and shows an inline `.dist-banner` (not a toast) with **Save schedule** (`Persistence.saveAll()`) / **Undo** when any kept child's bar resized, listing firmed ones (see the gap note below — the current `reconcileRuntimeSchedules` does NOT actually skip firmed tasks, contrary to this feature's own design doc). **Reset to work-center defaults** and **Undo last change** share the SAME dry-run/confirm/write pipeline (`_runWritePipeline`/`_postDistWrite`/`_confirmRemoval`/`_finishWrite`) rather than duplicating it. The detail panel's own **Reviewed** checkbox (including the indeterminate re-stamp) and **Show on Gantt**/**Open in Inspector** (via the ambient `NIMBUS.Selection`/`NIMBUS.Timeline.focus`, added to `frontend/types/nimbus-global.d.mts`) are wired. **Bulk actions** on the list's checked rows — **Mark {{n}} reviewed** / **Reset** — post `orders:[...]`, with any per-item 409/error listed in a `Modal.confirm` detail. **What-If guard**: `Sandbox.active` disables Save/Reviewed/Reset/Undo/bulk actions with hint `ui.dist_whatif_blocked`. Every OTHER status's list badge now has a real one-click action too: `incomplete` → Repair (re-posts the header's current stored shares unchanged), `runtime_mismatch` → `Persistence.saveAll()`, `separation_violated` → opens the detail then Show-on-Gantt; every multi-choice status (`mode_mismatch`/`wc_changed`/`membership_changed`/`below_min_lot`/`zero_quantity_children`) opens the detail panel, where the choice is made; `purged` stays a no-op per §6's own table.

**Known gap (documented, not fixed here):** aggregate_to_detail.md §6 says "`reconcileRuntimeSchedules` skips firmed tasks... the pane says so," attributing that to `persistence.mts:799`. The actual function (`frontend/optimization/engine.mts`'s `reconcileRuntimeSchedules`) has no firmed check at all — its own doc comment states "Firmed is parent-level only and does not suppress this required runtime correction." `distribution-pane.mts` calls it directly (verified safe: it takes a bare plant string and brackets its own Calendar run) and still surfaces firmed status on any resized child in the banner, but the underlying premise that firmed children are excluded from this pass is doc drift in aggregate_to_detail.md, not current behavior — don't "fix" the pane to skip firmed children to match the stale doc without re-verifying `reconcileRuntimeSchedules` first.

**Deferred/skipped, with reasons:**
- **Deep-link routing** (`#gantt/distribution?batch=<id>&order=&material=`, `?bucket=needs_review` auto-selecting a row/filter) — not wired. `App.gotoGanttSub`/`_GANTT_SUBS` don't currently pass extra params through to a sub-pane's `render()`, and extending that shell mechanism cleanly was judged non-trivial for this task's scope (root `CLAUDE.md`'s cross-domain-reach convention would need a real signature change in `application-shell.mts`, outside `frontend/distribution/`) — left for a follow-up task rather than reworked here.
- **Editor virtualization** (§6: a `VirtualList` once a header has more than ~12 shares) and the optional stacked-bar visualization are not implemented — the editor renders a plain table regardless of row count. Fine at the pilot's actual work-center sizes; a real gap at the Production Scale Roadmap's target scale.
- **A work-center member with literally no share row yet** (freshly joined, no planner has weighted it) does not appear as an editable row — the editor's row set is `GET .../{order}/{material}`'s `shares[]` (every share the header already knows about, including 0-weight/purged), not the work center's live membership list, which would need an additional per-plant members lookup this task did not add.
- `backend/distribution/CLAUDE.md`'s own "still open (P2-16)" line in its Counterpart section is now stale (this task shipped against it) — it lives outside this task's file scope (`backend/`) and was intentionally left unedited; update it in the same pass that next touches that file.

**The Work Centers admin tab (§4.3, P1) is NOT in this folder** — despite this file's own earlier draft saying otherwise, that work actually landed as `WorkCenters` inside `frontend/master-data/admin-ui.mts` (`PUT /distribution/{plant}/workcenters/{wc}`'s frontend counterpart). This folder is the Scheduling Board Distribution tab only.

## A real backend-shape correction worth knowing before touching this file

`aggregate_to_detail.md` §6's prose says the machine→work-center map comes from "`Store.masterData.workcenters`" and that `NimbusMasterLine` gains `sap_workcenter`/`distribution_weight` — **that's not what shipped.** Only `NimbusLineSetting` (`Store.lineSettings[machine]`) gained `sapWorkcenter`/`distributionWeight`, and there is no `Store.masterData.workcenters` cache anywhere in the app. `distribution-pane.mts` follows the real, already-established pattern instead: its own module-local `_workcenters` cache, fetched straight from `GET /master-data/sap_workcenter?plant=` and re-fetched on plant switch — the exact same shape `WorkCenters._rows` in `master-data/admin-ui.mts` already uses. Don't "fix" this file to read a `Store.masterData.workcenters` field that doesn't exist.

## Integration points

**Imports in:** `../platform/foundation.mjs` (`Config`, `Util`, `ErrorLog`, `Toast`, `Modal`), `../platform/store.mjs` (`Store`, `UndoStack`), `../security/session.mjs` (`Session` — `isAdmin()` gates the empty state's "Open Work Centers" button, `setPref()` persists filter state), `../insights/services.mjs` (`loadDistributionSummary`, called after a review write so the nav badge/Dashboard/Ctrl+K counts refresh immediately), `./shares-editor.mjs` (the P2-16 pure logic module). **P2-16 additions, real cross-domain imports** (verified one-directional — grep confirms nothing in `optimization/`/`scheduling/` imports `distribution/` back, so these are plain edges, not new cycles): `../optimization/sandbox.mjs` (`Sandbox`, the What-If guard), `../optimization/engine.mjs` (`Engine`, for `reconcileRuntimeSchedules`), `../scheduling/persistence.mjs` (`Persistence`, for `saveAll()`). Reaches shell navigation (`App.goto`/`App.gotoMasterSub`), `EmptyState.render`, and (P2-16) `Selection.set`/`Timeline.focus` for Show-on-Gantt/Open-in-Inspector, through the ambient `NIMBUS` global (`frontend/types/nimbus-global.d.mts`), the same idiom `frontend/master-data/material-grids.mts` uses — NOT a real import, since this is a leaf pane and shell already imports it downward (see next line).

**Imported by:** `frontend/shell/application-shell.mts` imports `DistributionPane` directly (the same way it already imports `Table`/`Timeline`/`WorkCenters`) and calls `.init()`/`.render()`/`.setActive()` from `App.gotoGanttSub`'s `'distribution'` branch.

**Endpoints called:** `GET /distribution/{plant}` (list, paged 50), `GET /distribution/{plant}/{order}/{material}` (detail), `POST /distribution/{plant}/review` (single-header and bulk), `POST /distribution/{plant}/{order}/{material}/shares` (dry-run preview and real write — Save/Undo/Repair), `POST /distribution/{plant}/reset` (dry-run preview and real write, single-item and bulk `orders[]` — Reset), `GET /master-data/sap_workcenter?plant=` (work-center combobox source + the "has a distribute-mode work center" empty-state check).
