## Admin sub-tabs (2026-10-30)

The Admin tab is a strip of sub-tabs, in order: **Overview** (`data-sub="overview"`, pane `#admin-overview-pane`), **Logs** (`logs`, `#admin-logs-pane`), **Diagnostics** (`diagnostics`, `#admin-diag-pane`), **Order Maintenance** (`order-maintenance`, `#admin-order-maint-pane`; upload, purge, upload history; renamed from the old "Data Operations" inner tab), **Jobs** (`jobs`, `#admin-jobs-pane`), **Manage Data Tables** (`manage`), **Interface**, **Security**, **System Configuration**, **Table Browser**. `AdminCockpit.gotoSub(sub)` (public) calls `_setSub`; every "Open ..." fix button and the Overview's "Open Logs" go through it (a button carrying `data-nav` jumps to that sub-tab). The old inner sub-sub tabs (Diagnostics / Data Operations / Logs & Audit / Thread under the Overview tab) and `gotoOvTab` are gone; the `.admin-ov-tabs` rule survives only because the Jobs pane still renders its own sub-sub row with it, and Manage Data keeps `.md-table-nav-row`.

- **Overview** (`admin-ui.mts`): the signal board (`#ov-signals`), Needs attention (`#ov-attention`), Recent activity (`#ov-recent`, 10 one-line rows, source badge through `ulog.src_*`). `_refreshOverview({force, clientOnly})` is two-tier: the **fast tier every 30 s** (`OV_FAST_MS`: `/health`, `/logs/backend` counts, the Jobs summary and runs, the SAP status for the selected plant) and the **slow tier every 5 min** (`OV_SLOW_MS`: `/diagnostics/db`, audit log, upload audit), run on `force` or when older than five minutes, keeping the last good slow data when a read fails. `_ovSeq` is the stale-response guard (a newer refresh drops an older response; `clientOnly` does not bump it). Pause / Resume (`#ov-pause`) stops only the timer; Refresh (`#ov-refresh`) forces both tiers. A 1 s ticker (`_ovTick`) repaints only the "refreshed ... ago" meta line. The polling timers run only while the Overview is the active sub-tab and the Admin tab is showing. `_renderSignals` skips the repaint when nothing the planner can see changed (`_ovSigKey`) and restores focus to the same fix or Details button; "measured ... ago" shows only for readings a minute or older.
- **`signals.mts`** (pure, no DOM): `buildSignals` returns seven signals worst-first (ties keep the order jobs, database, backend, data load, connections, SAP, browser); `buildAttention` returns at most eight "needs attention" items, one per cause. A failed read is never silently ok (`sig.unavailable`); a 403 or a non-admin viewer on an admin-only source is `sig.admin_only`. This browser's autosave state reads the same `Persistence.storageInventory()` the Diagnostics client card uses. Fix ids dispatched by `_onSignalFix`: `jobs.rerun`, `jobs.open_run`, `db.vacuum_all`, `db.vacuum_table`, `logs.open`, `data.reload`, `data.color_wheel`, `client.reset`, `nav.diagnostics`, `nav.interface`, `nav.order_maintenance`, `nav.jobs`; the admin-only ones are also refused client-side for non-admins (the server still gates).

| Threshold (`THRESHOLDS`) | Value | Effect |
|---|---|---|
| `dbPingWarnMs` / `dbPingErrMs` | 500 / 2000 ms | database ping warn / error |
| `poolWarnPct` / `poolErrPct` | 60 / 85 % | connection pool (same rule as Diagnostics) |
| `longQueryWarnS` | 30 s | long-running query warn |
| `slowQueryWarnMs` / `slowQueryErrMs` | 100 / 500 ms | slow query (mean) |
| `backendErrWarn` / `backendErrErr` / `backendWarnWarn` | 1 / 5 / 20 | backend errors and warnings in the window |
| `heapWarnPct` | 80 % | browser heap |
| `errRateErrPerMin` | 10 / min | browser error rate |
| `dbStatsStaleMs` | 600 000 ms | database stats reading counted as stale |

The server's `needs_vacuum` flag is trusted (an empty table never sets it; see `backend/admin_ops/CLAUDE.md`).

- **Logs** (`unified-log.mts` pure model, `unified-log-pane.mts` DOM): one merged timeline over seven sources: Backend (`/logs/backend`), This browser (the `ErrorLog` ring), Optimization & color wheel (`/audit/log`), Uploads (`/upload/audit`), Job runs, SAP runs and Order changes (`GET /schedule-events/{plant}/recent`, plant picked in the Logs filter). Caps: 200 rows per backend/audit read, 100 events, 50 runs; merged set capped at 2000, list shows 500 then 200 more per "Show more". **"Plant plus global" rule:** a plant filter keeps that plant's entries AND entries with no plant (backend rows without plant context, browser rows without one, scheduler heartbeats); untick Backend and This browser for a plant-only log. Filters (level, sources, user, plant, search) persist in `localStorage` under `nimbus.ulog.filter`. The context rail ("Related") for the selected row groups by **exact ids only**: request id (`rid`), error code, action id, order id, run id; plus one time-window group by user that is always labelled "possible". A UUID group key shows its first 8 characters with the full id in the `title`; "Filter to this" sets the exact-id filter. A selection that the current filters hide is cleared (rail shows the empty hint). `UnifiedLogPane.refreshFrontend()` (the `ErrorLog.subscribe` hook, no network) is debounced 300 ms trailing. At 720 px and under the four Clear buttons collapse into one "Clear..." chooser (`#ulog-clear-menu`, `Modal.choose`) that clicks the same hidden buttons, so every confirm flow is unchanged. The 30 s poll runs only while the sub-tab is active and the document visible. All log text is written with `textContent`. The source row shapes are shared types: `BackendLogEntry`, `AdminAuditLogItem`, `AdminUploadAuditItem` are exported from `admin-ui.mts` and `LogEntry` from `platform/foundation.mts`; `unified-log.mts` re-exports them and keeps `RecentScheduleEvent` and `SapInterfaceRun` local.
- **Diagnostics**: the client card, data pipeline, backend warnings, the database deep dive, and last (collapsed by default, `<details id="admin-thread-card">`) the Main Thread Profiler (`thread.*` keys; its Clear button stops the click from toggling the section). Caps through `AdminCockpit._capList(items, cap, render, host)` with a "Show all N" / "Show fewer" toggle (`btn.show_all_n`, `btn.show_fewer`): table cards 10, index bars 15, backend warnings 20, machines per line bar 15; at or under the cap there is no button.
- **Order Maintenance**: the Upload card now has the `#admin-upload-detail` host that distribution warnings render into (it was missing before 2026-10-30).

**Fit to measure (owner, needs the running app; the 2026-10-30 design pass checked 375 / 640 / 1024 but not 1440 px, and not all five locales):** the ten-label sub-tab strip at 1440 px (it scrolls sideways under 720 px); the `.sig-name` column with fr "Chargement des données" and de "SAP-Schnittstelle"; the fix buttons on one row with de "Jetzt erneut ausführen" and fr "Ouvrir la roue des couleurs"; the Jobs reason with a long job name at 375 px; `ov.refreshed_ago` + `ov.auto_every` beside Pause and Refresh at 375 px; the Logs filter bar and the two-column Sources fieldset at 640 px; the attention sentence plus its button in fr; the "Clear..." chooser options in de / es / fr; the one-line Recent rows with the longest source badge (de "Optimierung und Farbrad"-style labels) at 1440 px; the rail group headers with long order ids.
