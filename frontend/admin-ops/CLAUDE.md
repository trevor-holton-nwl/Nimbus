# Admin Ops — pointer

Substantive docs for this domain live at `backend/admin_ops/CLAUDE.md`.

## Logs tab (frontend ring + backend ring)

`admin-ui.mts` Logs: `#admin-log-export-json` calls `ErrorLog.exportJson()`; `#admin-log-user` sets `_logFilter.user` (exact match on `LogEntry.user` in `_getFilteredEntries`, also used by Copy filtered). `#admin-backend-log-user` is created lazily beside `#admin-backend-log-q` and sends `user=` to `GET /logs/backend`.

## Schedule event retention input (2026-10-23)

System Configuration (`admin-ui.mts`) has an order-history retention number input (`#sc-retention-days`, 1-60, default 14) read from and saved in the same `/system-settings` POST as the order-field visibility settings (`schedule_event_retention_days`); the server rejects values outside 1-60 with a 400. Details: `backend/schedule_events/CLAUDE.md`.

## Jobs tab (2026-10-29)

The Admin > Jobs tab (`jobs-model/client/pane/dialog/run-detail.mts`, sub-tab strip beside the others) drives `backend/jobs/`; the run summary carries `steps`, counts and `action_id`. Substantive docs: `backend/jobs/CLAUDE.md`.

- **Control ids are per sub-view** (`jobs-*`, `jobs-runs-*`, `jobs-up-*`): the three views stay in the DOM side by side, so a shared id answered `getElementById` with a hidden copy (pinned by `tests/modules/admin-ops/jobs-pane.test.mjs`). A new job opens as **Apply** (W1 ruling; Dry run is the alternative), seeded from `GET /jobs/types` `defaults`. The log viewer pages (`limit=2000`, keeps reading while a page is full), the runs poll merges page 1 into loaded pages, the 7-day strip says so when the server's 50-entry cap ends before the week, and Escape / X ask before discarding a dirty form.
- **W1 run status (2026-10-28, branch `w1-run-status`, not merged):** SAP-style, no approval inbox. A new job defaults to **Apply**; the stored value `propose` is shown as **Dry run** (viewable proposal, no Approve/Discard anywhere; `jobs-run-detail.test.mjs` pins that). Status labels: scheduled = Queued, succeeded = Finished, warning = Finished with warnings, plus Skipped(reason) and **Missed** (a skipped run whose error starts `missed:`; `displayStatus`). A health strip (`#jobs-health`, `GET /jobs/summary`, `.kpi-tile.is-actionable` buttons: Running, Queued, Failed 24 h, Missed, Next fire) filters the Runs list through `_tileClick` (Failed / Missed add `since_hours=24`), with a scheduler-heartbeat badge (stale after 3 min). The pane polls every 30 s only while a run is active (15 s while a run started here is watched; a completion toast with a View action fires once per watched run). Run detail: failed runs open on an Error panel (`error_kind` badge "Fix the job" / "System error", failing step, message), log viewer gained errors-only, First error, an elapsed column, structured `data` collapsed under its line (row heights are estimated), copy/download errors, a flexible height (`50vh`, min 240 px, max 60vh), a neutral single-fill step bar (only the failed step takes `--err`), `.kpi-tile` result tiles, a "running longer than usual" badge, and Restart. Dry runs add a read-only proposal table (`VirtualList`, first 200, "Finish now" -> "Finish proposed", delta). The dialog uses Flatpickr for time, date and date-time (original input keeps the machine value, so `readForm` is unchanged; native inputs remain without flatpickr). Also: loading skeleton rows (`aria-busy`) and a Retry button on errors, plant-zone suffix (`tzShort`) on times, `/` focuses the search or plant filter, periodicity and started-by filters on Runs, a bulk bar over loaded rows (sequential PATCHes, one summary toast). `jobs-locales.test.mjs` pins every `jobs.*` key in all five locales.
