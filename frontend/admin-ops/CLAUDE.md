# Admin Ops — pointer

Substantive docs for this domain live at `backend/admin_ops/CLAUDE.md`.

## Logs tab (frontend ring + backend ring)

`admin-ui.mts` Logs: `#admin-log-export-json` calls `ErrorLog.exportJson()`; `#admin-log-user` sets `_logFilter.user` (exact match on `LogEntry.user` in `_getFilteredEntries`, also used by Copy filtered). `#admin-backend-log-user` is created lazily beside `#admin-backend-log-q` and sends `user=` to `GET /logs/backend`.

## Schedule event retention input (2026-10-23)

System Configuration (`admin-ui.mts`) has an order-history retention number input (`#sc-retention-days`, 1-60, default 14) read from and saved in the same `/system-settings` POST as the order-field visibility settings (`schedule_event_retention_days`); the server rejects values outside 1-60 with a 400. Details: `backend/schedule_events/CLAUDE.md`.

## Jobs tab (2026-10-29)

The Admin > Jobs tab (`jobs-model/client/pane/dialog/run-detail.mts`, sub-tab strip beside the others) drives `backend/jobs/`; the run summary carries `steps`, counts and `action_id`. Substantive docs: `backend/jobs/CLAUDE.md`.

- **Control ids are per sub-view** (`jobs-*`, `jobs-runs-*`, `jobs-up-*`): the three views stay in the DOM side by side, so a shared id answered `getElementById` with a hidden copy (pinned by `tests/modules/admin-ops/jobs-pane.test.mjs`). A new job opens as **Apply** (W1 ruling; Dry run is the alternative), seeded from `GET /jobs/types` `defaults`. The log viewer pages (`limit=2000`, keeps reading while a page is full), the runs poll merges page 1 into loaded pages, the 7-day strip says so when the server's 50-entry cap ends before the week, and Escape / X ask before discarding a dirty form.
- **W1 run status (2026-10-28, branch `w1-run-status`, not merged):** SAP-style, no approval inbox. A new job defaults to **Apply**; the stored value `propose` is shown as **Dry run** (viewable proposal, no Approve/Discard anywhere; `jobs-run-detail.test.mjs` pins that). Status labels: scheduled = Queued, succeeded = Finished, warning = Finished with warnings, plus Skipped(reason) and **Missed** (a skipped run whose error starts `missed:`; `displayStatus`). A health strip (`#jobs-health`, `GET /jobs/summary`, `.kpi-tile.is-actionable` buttons: Running, Queued, Failed 24 h, Missed, Next fire) filters the Runs list through `_tileClick` (Failed / Missed add `since_hours=24`), with a scheduler-heartbeat badge (stale after 3 min). The pane polls every 30 s only while a run is active (15 s while a run started here is watched; a completion toast with a View action fires once per watched run). Run detail: failed runs open on an Error panel (`error_kind` badge "Fix the job" / "System error", failing step, message), log viewer gained errors-only, First error, an elapsed column, structured `data` collapsed under its line (row heights are estimated), copy/download errors, a flexible height (`50vh`, min 240 px, max 60vh), a neutral single-fill step bar (only the failed step takes `--err`), `.kpi-tile` result tiles, a "running longer than usual" badge, and Restart. Dry runs add a read-only proposal table (`VirtualList`, first 200, "Finish now" -> "Finish proposed", delta). The dialog uses Flatpickr for time, date and date-time (original input keeps the machine value, so `readForm` is unchanged; native inputs remain without flatpickr). Also: loading skeleton rows (`aria-busy`) and a Retry button on errors, plant-zone suffix (`tzShort`) on times, `/` focuses the search or plant filter, periodicity and started-by filters on Runs, a bulk bar over loaded rows (sequential PATCHes, one summary toast). `jobs-locales.test.mjs` pins every `jobs.*` key in all five locales.
- **W1 fix wave (branch `w1-fixes`):** one poll owner (`_pollTimer`: 15 s watching / 30 s running / 60 s idle, so the heartbeat badge never freezes; the Runs timer only refreshes the list), `_healthSeq` guard, skeleton tiles + Retry, `_setHtml` skips unchanged repaints and a small `.job-sr` status node (`#jobs-live` / `#jobs-runs-live`) replaces `aria-live` on the list hosts; the quiet Jobs poll merges page 1 (`_jobPages`); the Runs tab has its own `_runStatus` / `_runType` (a health tile no longer touches the Jobs tab's Last run filter) and a Type select; Failed tile shows the config/system/changed split; `transient` error kind ("Board changed, run again"); error-panel jump buttons stay hidden until the log has an error line; proposal column "Now", banner lines say what is compared (lists, setup, calendar, tools; not orders) and that a real run may skip moves; Restart / row Restart confirm names the job's CURRENT mode; bulk bar re-entrancy guard; `/` ignores a hidden target; combobox document listeners are aborted by id. `jobs-hidden-css.test.mjs` now also checks any single-class display rule used on a `hidden` template element.
- **W2 generic params form, window picker, report viewer (2026-10-30, branch `w2-reports`, not merged):** the dialog no longer hardcodes the optimizer. `JobForm` is `{jobType, name, plant, params, recur, ...}`; the params block renders from `GET /jobs/types` `params` (`jobs-model.mts` `ParamMeta` / `TypeMeta`, `jobs-dialog.mts` `paramHtml`): enum -> select, boolean -> checkbox, integer / number -> number box with min / max, multi_enum -> checkboxes, string -> text, `date_window` -> the window picker; control ids are `jb-p-<param>` (window: `jb-p-<param>-choice|from|to|n|anchor|foff|toff|unit|line`). Labels are `jobs.p.<type>.<param>[.<value>]` with the schema title / raw value as fallback; the optimizer keeps its pre-W2 strings through `LABEL_ALIASES` (mode, search, firmed, result, and `search.hint` = the Exhaustive duration note); Apply / Dry run keeps its value-driven sentence under `apply_mode`, and `apply_mode` renders only for an action type that has it (`hasApplyMode`) and is disabled for a non-admin. Client validation is `validateParams` + `validateWindowUi` (errors under `jb-err-p-<param>`, `errs.params`); the server re-validates. The type select is grouped Optimization | Reports, locked once a job exists; changing the type of a NEW job re-seeds the params from that type's defaults. The Jobs and Runs type filters list every type grouped the same way; report jobs and runs carry a Report badge.
  - **Window picker:** one select (Fixed dates | Older than N days | Last N days | Next N days | Since the last successful run | This week | This month | Custom: anchor, from / to offset, unit) plus the fields that choice uses, Flatpickr on the fixed dates, and a live debounced "Resolves today to <from> to <to> (<tz>, plant time)" line from `POST /jobs/windows/preview` (`winSeq` stale guard; an error such as "no timezone" shows on the line as an error). `windowToUi` / `uiToWindow` mirror the backend presets; switching to Custom keeps the meaning of the preset it left. No new Store events.
  - **Report viewer** (`jobs-run-detail.mts`): a report run shows its row counts as `.kpi-tile`s (`row_counts`, tile labels `jobs.a.tile.<section>`), the resolved window ("Window: 2026-09-28 to 2026-10-28, plant time"), and one labelled table per section (`role=table`, `VirtualList`, section titles / column labels `jobs.a.sec.<key>` / `jobs.a.col.<key>` falling back to the server's English). The first page of every section is one request (offset 0, limit 500); a longer section is read on in pages of 500 in the background with a "Loading rows" count. Per-section Download CSV fetches `format=csv` (BOM and formula guard come from the server); a truncated section says "first N of M"; it works while polling because the runner stores the artifact before the run finishes.
  - Tests: `tests/modules/admin-ops/jobs-types-fixture.mjs` loads `tests/fixtures/jobs_types.json` (the live registry dump, kept equal by `tests/test_jobs_contract.py`); `jobs-model|dialog|client|run-detail|locales|pane.test.mjs` cover the generic form, the picker, validation, the artifact builders and the `jobs.*` locale families. Fit measurement (5 locales x 4 widths) is owner-owed: see the list in the branch report.
