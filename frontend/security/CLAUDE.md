## Sign-out and shared PCs

`Session.signOut(opts)` clears local planner data (`clearLocalPlannerData()`: the legacy `nimbus.state.v3` key, every `nimbus.cache.*` key (records, quarantine; the marker last) and `CacheStore.wipe()`, `nimbus.recentCmds`, `nimbus.patterns.v1`, `nimbus.calendar.pendingDeletes`, sessionStorage; keeps `nimbus.theme`/`nimbus.locale`) and confirms first when the shell-supplied `Persistence.hasPendingWork()` is true (dirty/force/conflicted/firm-dirty ids, queued calendar deletes, What-If active). An **expired** login (12h `Config.SESSION_MAX_AGE_MS`, checked at the boot gate) does the same wipe through `Session.clearExpired()` — session blob plus `clearLocalPlannerData()`, theme/locale kept — but WITHOUT the unsaved-work confirm: the expired session's unsaved work is discarded (owner ruling 2026-10-06). It runs pre-boot, so there is no autosave to cancel. The admin "Reset client state" action calls `clearLocalPlannerData({ keepQueuedWork: true })`, which keeps `nimbus.calendar.pendingDeletes` (queued unsent deletes are work, not history). Known gap: unsaved admin-form edits (setup, master data) are not detectable, so sign-out does not warn about them.

**Compact cache wipe, halt and resume (2026-11-04).** Sign-out, the 12 h expiry and admin Reset wipe the cache synchronously (`CacheStore.wipe()` plus the key sweep in `clearLocalPlannerData`; the marker is removed last so a racing tab cannot rebuild it from records still there). Sign-out and Reset call `CacheStore.halt()` first so no late autosave rewrites what was cleared. A halt lifts only through `CacheStore.resume(user)` at sign-in (`Session.signIn` path, which then runs `sweepOrphans`) or `CacheStore.resumeSameUser(user)` on a `storage` event, and the latter only for the user this page booted or signed in as (`CacheStore.setPageUser`, named at the boot gate and in `signIn`); a `ready(otherUser)` while halted latches "sign-in required" until `signIn`. Every resume clears the tab's peek and fires `CacheStore.onResume` once so `Persistence` re-stores its in-memory edits, and `write()` refuses any user other than the page user. A `storage` listener on `nimbus.session` halts this tab when another tab signs out or a different user signs in (and toasts `toast.cache_halted_other_tab`); a late session write cannot lift the halt while this page is leaving. `CacheStore.sweepOrphans(user)` runs at the boot gate (`Session.sweepOrphanCache`, `app.js`) and deletes other users' records and empty records the marker does not point at; a record holding rows for the signed-in user is never deleted. The expiry path (`Session.expiredEditCount()` read before `clearExpired()`) reports how many unsaved edits the expired session discarded on the login screen; the 12 h rule itself is unchanged. Detail: `frontend/scheduling/CLAUDE.md`, "Compact cache record".

**SECURITY FOLLOW-UP (not done by this work).** The Time Machine history (IndexedDB `nimbus-intel`, `frontend/nimbus-intelligence.js`) and the ErrorLog ring snapshot (IndexedDB `nimbus-errorlog`, `frontend/platform/foundation.mts`) are NOT wiped on sign-out, expiry or Reset: no code in `frontend/` deletes either database. Time Machine snapshots hold task rows, so on a shared PC they outlive the sign-out. Decide whether to wipe or user-scope them.
