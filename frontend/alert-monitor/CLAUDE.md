# Alert Monitor — the profile-driven alert triage tab

Frontend half of the Alert Monitor (spec: `docs/superpowers/specs/2026-10-20-alert-monitor-design.md`; its "UI overhaul — rev 2" section describes the page as it is now, and its "Shipped vs deferred" section the first build). Backend half: `backend/alert_profiles/` (profiles + acknowledgements). The shared logic lives in `frontend/insights/` (see its CLAUDE.md); this folder is the page, its pure model and two modals.

## The vocabulary rule

Never user-visible on this page: "points", "pts", "exact", "estimate", "outside the confidence window", "cap". The only numbers shown are counts, dates / relative days and the confidence score (0-100); "Confidence 71 → 78" appears only for a replayed fix whose score changes (a lower after-score is shown too). Ranking is internal (`impactPoints`, `compareAlerts('impact')`, `groupAlerts` order, `LeverageItem.points`). A vocabulary-gate test in `tests/modules/locale-completeness.test.mjs` checks English `am.*` / `leverage.*` values only, against the regex `points?|pts|exact(ly)?|estimates?|estimated`; "outside the confidence window" and "cap" are conventions the gate does not check, and de/es/fr/pt are not gated. Don't add a string that breaks the rule, and don't render `points` anywhere.

## What lives here

- **`alert-monitor-pane.mts`** — `AlertMonitorPane`, the `#alerts-tab` page (`#am-scroll` is its scroll element). Lifecycle is the `DistributionPane` shape: the shell calls `init()` once (idempotent; wires the Store, `AlertProfileMatches` and `AlertProfileClient` subscriptions) on first entry, `render()` on every entry, `setActive(false)` on leave (`application-shell.mts`, `App.goto`). **`_active` gates every subscriber** — a hidden pane does no work, and `render()` sets `_levStale` because events were ignored while hidden. `_paint()` calls `_ensureShell()` (builds the static shell once; `_setHtml`/`_lastHtml` diff the HTML per region), then `_syncHeader`, the summary line, banner, prompt, Top fixes panel and groups, and **ends with `OverflowMenu.reconcile()`**. `resetView()` (also run on a plant change) clears folds, open diagnose panels, "Show all", the focus set and the Top fixes state. `setFocus(ids, title)` / `clearFocus()` implement the "Showing N alerts for: …" chip (a focused list bypasses the profile).
- **`alert-monitor-model.mts`** — pure builders; no DOM, no Store: translation is an **injected `t`**, and every interpolated value goes through the module's `_esc` once (don't escape again in a caller; a double-escaped `title=` was a Task 12 bug). Header: `profileWindow`, `summaryLine`, `windowSummary`, `viewFor`, `MONITOR_GROUP_BYS`, `MONITOR_SORTS`, `DEFAULT_GROUP_BY`. List: `visibleAlertsFor`, `horizonAlerts`, `emptyStateFor`, `rowActionsFor`, `rowPrimaryActions`, `rowPrefix`, `rowHtml`, `groupCounts`, `groupMenuItems`, `groupHeadHtml`, `groupLabel`, `diagnoseHtml`. Top fixes: `levTitle`, `levActions`, `fixClearsText`, `fixLineParts`, `fixRowHtml`, `fixesSectionHtml`, `levSummaryText`, `levPairsForReview`.
- **`alert-profile-editor.mts`** — `AlertProfileEditor`, the modal (`#modal-alert-profile`, body `#ape-body`, footer `#ape-foot`). `open({plant, profileId?, fromPicker?})` is called from the page's Edit / View rules button, the picker's "+ New profile…" option (`fromPicker: true`) and the zero-profiles prompt, and **never from inside the User Settings modal** (settings closes itself and navigates to the tab instead). Left rail = the plant's profiles, right = the draft form; typing never re-renders the body (it would drop focus), only the live day range, live match count and structural changes touch the DOM. **Validation is not re-implemented:** `validateProfile` (`insights/alert-profiles.mts`) returns i18n keys per field path and the editor only renders them. **Permission model** (`canDeleteProfile`): an admin or the creator (`created_by`, case-insensitive) may edit/delete; anyone else sees a read-only form with a Duplicate hint. Duplicate and "Copy to plants…" (searchable multi-select of accessible plants) create new rows; a server 409 `stale` surfaces as a stale-edit message. There is **no Default ranking field**: `profileFromDraft(draft, existing?)` sends `ranking: 'impact'` for a new profile and passes an existing profile's `ranking` through unchanged. With `fromPicker`, a successful create calls `AlertProfileMatches.setSessionProfile(newId)` so the page views it (an edit re-selects only when it is the viewed profile).
- **`alert-ack-modal.mts`** — `AlertAckModal.open({plant, alertId?, alertIds?})` over the static `#modal-alert-ack` (Modal's central focus trap, which returns focus to the opener). One `alertId` takes the single path (`AlertAcksClient.acknowledge`); several `alertIds` (a group's "Acknowledge N…") show the title `am.ack_title_n` and make one `AlertAcksClient.acknowledgeMany` call (the client splits it into sequential POSTs of at most 500 ids, the server cap, with one refetch and one notify at the end; a failed chunk counts its ids as `failed`, so the partial toast is real), with toast `am.ack_bulk_done` / `am.ack_bulk_partial`. `validateAck` is pure: reason required, trimmed, at most 200 characters; `until` is the picked day sent as **naive local** `YYYY-MM-DDT23:59:59` (end of that day, so "until the 27th" hides through the 27th), or `null` with "No end date". Never an offset or `Z` (server convention: `backend/alert_profiles/CLAUDE.md`, "Naive local time"). The client refetches and fans out so every list repaints itself; the modal never touches the Store.

## Page anatomy

`.am-head` then `#am-scroll`.

1. **Title row** — `h2.am-title`, the plant badge, the `.us-combo` profile combobox (All alerts, the plant's profiles, a final "+ New profile…" option), the Edit button ("View rules" when `canDeleteProfile` says no; hidden under All alerts), "Your default" text or a "Set as default" button, and the ⋯ page menu (checkbox items for the Gantt highlight and Show acknowledged). **`NEW_PROFILE_ID = '__new__'`** is the new-profile option's sentinel: `choose()` intercepts it and opens the editor; `_chooseProfile` rejects any id not in `_comboOptions()`, so it never reaches `setSessionProfile`. The viewed option's `windowSummary` is a muted second line and the input's `aria-description`.
2. **Summary line** (`#am-summary`) — `summaryLine(...)`: the lead clause (profile window `am.summary_window`, `am.summary_profile`, `am.summary_all`, or the focus-chip text), then error / warning / order clauses (zero omitted, `_one` keys at 1), then the `button.am-summary-conf` "Plant confidence N" that opens `Confidence.showBreakdown()`. Counts are over the alerts the list shows; orders are the distinct `taskId ∪ peerId`.
3. **Controls row** — the Group by `<select>` (Machine, Day, Type, Category, Order, None) and the Priority / Date switch. `alertMonitorView[profileId] = {groupBy?, sort?}`; `_persistView` writes only the changed key. `viewFor`: stored `groupBy` as-is else **Machine** (`line`); stored `sort` `time`/`impact`, stored `severity`/`orders` coerce to `impact`, else `profile.ranking === 'time'` gives `time`, else `impact`.
4. **Banner and zero-profiles prompt**, then **Top fixes** (`#am-leverage`), the focus chip, and the **groups** (`#am-groups`).

**Top fixes** (`section.am-fixes`): a ranked list built by `fixesSectionHtml`. Rendered whenever the plant has alerts, on all of the plant's alerts (D10), independent of the viewed profile. **Partition first, then slice**: non-`adminOnly` items form the main list (first `LEV_TOP_N = 5`, "Show 10 more" adds `LEV_STEP = 10` per click, never more than `LEV_MAX_RENDER = 50`); for a non-admin the `adminOnly` items sit under a collapsed "Needs an admin (N)" disclosure (`_levAdminOpen`, no rank numbers, also capped at 50); an admin sees one list. Each row: rank, title, a second line (`fixLineParts`: "Clears N alerts on M orders", the confidence clause only when `method === 'replay'`, not `requiresMinutes`, and the score changed, `am.lev_no_headroom`, `am.lev_remaining`), one primary button and a ⋯ menu (`levActions` returns `{primary, menu}`; for an admin-only fix a non-admin's primary is "Copy summary for owner").

**Groups and rows.** `ROW_H = 44` (also the `VirtualList` row height in group-by None; `DIAG_H` is added under an open diagnose panel); `GROUP_ROW_CAP = 40` rows per group before "Show all N". The row grid is `14px minmax(0,1fr) 240px auto`: the when column is **240 px** (the longest localised overdue string measures about 238 px) and `.am-acts` is a **fixed width** (240 px, 136 px below 1,200 px, `auto` at 720 px and below) so the when column aligns across rows; below 1,200 px the Fix / Override label collapses to its glyph. Row = severity glyph, `rowPrefix` (the non-empty parts of `[line, orderNo]` minus the part the active group-by says and minus a line the message names), the message, the when column, then Go to / Fix-or-Override / ⋯. The group head is 36 px: toggle (caret, glyph, label, count badges), **Move N orders** (visible at 2 or more) and a ⋯ menu (Go to, Move N orders, Open these N orders in the table, Acknowledge N…). **Move N orders** (`_moveGroup` → `_runBatchMove`): N counts distinct orders (`groupCounts.movableOrders`); movable types are `MOVABLE_ALERT_TYPES` (`overlap`, `blackout`, `tool-conflict`); blocked in What-If; confirms above `GROUP_MOVE_CONFIRM_ABOVE = 5`; runs `Alerts.applyFix(id, {quiet: true})` per alert in list order, skipping ids gone from `Store.alerts` and alerts naming an already-moved order; one summary toast; try/catch/finally so the summary, repaint and head focus always run. Undo is one entry per order, and `UndoStack.MAX = 10` keeps only the last 10 of them; the confirm text says so (`am.group_fix_confirm`: "Undo keeps the last 10 moves"). Singular forms exist for the menu item (`am.group_fix_n_one`) and the summary leads (`am.summary_*_one`).

## The Top fixes render loop (`_levRun`)

Fixes are computed in two phases so the alert list never waits on them:

1. `_levScheduleFirst()` defers the first run one tick (the list paints first). `_levRun` builds the input (`_levDeps.buildInput`, over `buildPlantSnapshot`), runs **`groupLeverage`** (pure, immediate), sets `_levHave`, and paints — **phase 1**, removal numbers only.
2. Unless `_levSkipAnalysis()` (Sandbox active or `OptimizerPreview.active`), it awaits **`analyzeLeverage`** through the worker-backed runner (`Compute.leverageBatch`), re-applies any minutes the user typed (`_levTyped` -> `replayWithMinutes`), and paints again — **phase 2**, replayed numbers.

What keeps it correct: **one in flight** (`_levInFlight`; a request during a run sets `_levRerun` and re-queues afterwards); the **`Store.rev()` stale guard** (`rev0` is read before the work; if the plan moved, the result is dropped and re-queued through `_levDebounced`, at most `_LEV_MAX_STALE_RETRIES = 3` times); a **400 ms debounce** (`_LEV_DEBOUNCE_MS`) on `alerts:change`, `tasks:bulk*`, `setup-snapshot:replace`, `calendar:change`, `blocks:change`, `plantBlocks:change`; a half-typed minutes box survives an unrelated repaint (`_renderLeverage` returns while `.am-fix-min-input` has focus) **except** the repaint that shows that box's own result — `_levMinutesEntered` sets the one-shot `_levForcePaint` around a synchronous `_paint()` (it relies on `_paint` staying synchronous); an Enter and a Replay click on the same row are de-duplicated (`_levReplaying`). A `requiresMinutes` row asks for minutes ("Setup minutes" box + Replay), never shows a prediction.

## Action vocabulary

Row actions are `focus | fix | override | diagnose | ack | unack` — **no `dismiss`**: Acknowledge is the only "make it go away" verb on this page (Dismiss stays in the drawer, and `Alerts.dismiss` is untouched). Buttons and ⋯ menu items carry the same `data-alert-action` / `data-alert-id` (+ `data-task-id`) and both end in **one dispatcher**, `_runAlertAction` (button clicks through `_onAlertAction`, menu items by calling it directly); calls match the drawer (`AlertsUIAdapter._handleAction`). Eligibility comes from the shared **`FIXABLE_ALERT_TYPES` / `OVERRIDE_ALERT_TYPES` / `CALENDAR_ALERT_TYPES`** exported by `insights/alert-profiles.mts`, which the drawer, the cell card, the monitor model and the Gantt all import (a parity test over `FIRING_ALERT_TYPES` pins it). Fix and Override are no-ops in What-If and render `aria-disabled` with the `am.whatif_blocked` hint. Fix-row actions (`_onLevAction`) add: `show-alerts` (focus + `AlertProfileMatches.setFocusTaskIds`, so the Gantt follows the row), `open-table`, `copy-summary`, `goto`/`focus-first`, `diagnose-cell`/`diagnose-worst`, `cal-fix`, `edit-calendar`, `rg-workcenters`, `rg-routing`, `setup-review`/`setup-copy`, `optimize`, `replay-minutes`.

## OverflowMenu usage and focus return

Every ⋯ here is `OverflowMenu.open(anchor, items, {align: 'end', key})` (`frontend/platform/overflow-menu.mts`). The key is the row's alert id, the group key, the fix key or `page`. **The templates must render `data-ovf-key`** on each trigger (`rowHtml`, `groupHeadHtml`, `fixRowHtml` and the page-menu button do), and `_paint` ends with `OverflowMenu.reconcile()`: a menu whose trigger a repaint replaced closes or follows the same-key trigger. Focus rules: after Fix, Diagnose and Remove acknowledgement the pane repaints and `_restoreRowFocus` focuses the row's trigger (found by `data-ovf-key`), else the next row's, else the previous row's, else the group head (`_focusGroupHead`); Acknowledge and Override first `_refocusKey` the live trigger so the modal's own focus return lands on it; "Move N orders" ends on the group head; "Show 10 more" and the admin disclosure restore focus after their repaint.

## "View as" vs "Set as default"

"View as" calls `AlertProfileMatches.setSessionProfile(id)` — session-only, beats the pref **for this page only** (the pane reads `AlertProfileMatches.view()`; the Gantt, bell, drawer and Orders read `current()`, which ignores the override), until cleared or the plant changes, writes nothing. "Set as default" is the one control that writes the persisted pref (`alertProfileByPlant`: one key holding the whole `{plant: profileId}` map, then clears the session override). Group-by / sort per profile persist in `alertMonitorView`; the Gantt highlight toggle and "Show acknowledged" (both in the ⋯ page menu) persist as `alertProfileGanttHighlight` / `alertsShowAcknowledged`.

## The no-Store-event rule

Nothing here emits a Store event: `Store.emit()` bumps the revision and re-renders everything, and the fix list's stale guard reads that revision. Derived UI state (profile matches, profile and ack caches) travels on each module's own `subscribe()` fanout (`AlertProfileMatches`, `AlertProfileClient`, `AlertAcksClient`). The pane only listens to Store events, and only while `_active`.

## Scale notes

Everything is plant-scoped (profiles, acks, matches, the fix input); never fetch or render two plants at once. Each group card lists at most `GROUP_ROW_CAP` (40) rows until "Show all"; **group-by none** is the one unbounded list and renders through `VirtualList` (`_vl`; fixed row height `ROW_H`, a fixed `DIAG_H` diagnose panel). The Top fixes list renders at most `LEV_MAX_RENDER` (50) rows in the main list (a non-admin may see up to 50 more behind the admin disclosure). Default group-by Machine can paint about 70 x 40 rows: `_fmtDay` reuses one `Intl.DateTimeFormat` per language and `groupAlerts` de-duplicates `orderIds` with a Set; `tests/modules/alert-monitor/alert-monitor-bench.test.mjs` (skipped unless `NIMBUS_BENCH=1`) times 15,000 alerts across 70 lines. The profile picker is a searchable combobox, never chips.

## Gotchas

- The ack modal's Flatpickr `minDate` is the plant's today (`Util.dayKey(Util.plantToday(plant))`), not the browser's.
- `app.js` assigns `globalThis.NIMBUS = NIMBUS` after building the namespace: `const NIMBUS` is a script-scope binding, not a `window` property, so without that line every `_nim()` read here would be `undefined` (Go To, Override, Confidence, open-in-table all silently do nothing). `tests/modules/legacy-nimbus-global.test.mjs` pins it.
- `DistributionPane.openParent` exists for a distribution deep link, but nothing in this folder calls it yet.
- The editor compares `profileFromDraft(draft)` with the snapshot taken when the draft was loaded (`baseline`); rail switch / New / Duplicate / Copy ask `Modal.confirm` (`ape.discard_*`) when they differ. A non-409 save or delete failure shows the server message or `ape.err_save_failed`, never `ape.err_stale`.
- `am.window_all` is the only `am.*` key kept from the planned deletion list: `windowSummary` returns it for All alerts (the picker's second line and `aria-description`).
- The profile picker's "+ New profile…" row is a pinned footer: the options scroll inside `.am-opt-scroll` and the footer sits outside it, so it stays visible past the 240 px fold.
- Day-group heads and the when column use a short weekday/day/month label (`_fmtDay`), not `Util.fmtDT`; the exact date and time are in the when column's tooltip.
