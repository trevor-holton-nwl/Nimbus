# TypeScript Migration — Phase 4 (`schedule-data.mts` + backend API-contract, full scope) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the client↔server contract gap (`docs/typescript_migration.md` §F) for the highest-churn endpoint family — `GET /tasks` and the task-date-update path — by making `brain.py`'s Pydantic response models the single source of truth, generating TypeScript types from the live OpenAPI schema, and converting `web/schedule-data.mjs` (`Persistence`, `CalendarSync`, `Session`) to real, `tsc`-checked TypeScript against those generated types plus hand-written supplements for the endpoints this phase does not yet model on the backend.

**Architecture:** Three layers, each depended on by the next:
1. `brain.py` gains `response_model=` Pydantic classes for `GET /tasks`, `POST /task/update`, `POST /tasks/update`, `POST /tasks/bulk_update`, `POST /tasks/refresh`, `POST /tasks/baseline-correct` — the "update path" the 2026-07-28 resolved decision named. FastAPI now validates its own responses against these models at runtime, and its auto-generated OpenAPI schema becomes accurate for this endpoint family.
2. A one-shot Python→OpenAPI→TypeScript codegen pipeline (`scripts/dump_openapi.py` + `openapi-typescript`, wired as a manual `npm run generate:api-types`, **not** part of `npm run build`/CI) produces `web/types/api-generated.d.mts`, a committed, machine-generated `.d.mts` module.
3. `web/schedule-data.mjs` → `.mts`, importing the generated types for the endpoints Task 1 modeled, and hand-written local interfaces (matching this migration's existing per-file convention) for the endpoints it doesn't (`/health`, `/plant-calendar`, `/master-data/plants`, `/master-data/production_lines`, `/security/*`) — those are out of scope for backend typing this phase, but the frontend file that calls them must still compile with real types. `web/types.mts` gains the `NaiveLocalTs`/`IsoUtcTs` aliases and the `LiveState`/`StoredState` pair (§F/§G).

**Tech Stack:** `tsc` (existing), `pydantic` v2.13 (existing, already used for `TaskDateUpdate` etc.), one new dev-only tool: `openapi-typescript` (npm devDependency) — an accepted, scoped exception to the Phase 0 "tsc alone" philosophy, per the 2026-07-28 resolved decision.

## Global Constraints

Same zero-behavior-change discipline as Phases 1-3 on the frontend side: permitted edits are type syntax + non-null/type assertions + explicit fields for lazily-added properties + coercions matching existing implicit JS coercion; preserve every comment verbatim; always verify with `npm test`; don't edit `eslint.config.js`/`nimbus-compute-core.d.ts`/consumer files (`app.js`, `app-entry.mjs`) beyond the one-line migration-doc/CLAUDE.md mentions. Plus, new for this phase:

- **Backend response shape must not change, only be validated.** `response_model=` must declare every key the current hand-built dict literal returns — FastAPI silently *drops* any returned key not declared on the model (it does not error). A dropped key is a silent wire-contract regression the type system won't catch on its own; Task 1 requires an explicit key-set-parity test, not just "the code typechecks."
- **`import db` opens a real Postgres connection pool at module load** (`db.py`'s `ConnectionPool(..., open=True)`, `min_size` from `NIMBUS_PG_POOL_MIN`, default 2). `tests/conftest.py` already works around this for pytest collection by setting `NIMBUS_PG_POOL_MIN=0` before importing `brain`/`db`. The new `scripts/dump_openapi.py` (Task 2) must do the same — `api.openapi()` is pure route/model introspection and never touches the database, but the bare `import brain` (which imports `db`) would otherwise try to open warm connections on a machine where Postgres isn't running (per project memory, frequently the case locally).
- **The generated `web/types/api-generated.d.mts` is committed to git, not gitignored** — unlike the `.mjs` compiled outputs (regenerated by every `npm run build`), this file is regenerated manually only when a `response_model=`-backed endpoint's Pydantic model changes. Document the regen command plainly; do not wire it into `pretest`/CI (that would make every frontend build depend on a working Python + `brain.py` import, a much bigger footprint than this phase intends).
- **Two distinct date wire encodings already exist and must be modeled, not merged** (§F): the task-save path serializes via `Util.toLocalSeconds` (naive local, no `Z`); blackout writes serialize via `.toISOString()` (UTC, with `Z`). Use the `NaiveLocalTs`/`IsoUtcTs` aliases from Task 3 everywhere a wire timestamp is typed — never a bare `string` — so a future reader can tell which encoding a given field uses without re-reading `schedule-data.mts`'s implementation.
- **`schedule-data.mjs` must never import `schedule-services.mjs`** (only the reverse direction is allowed — see the file's own header comment). The injected `_calendarService` seam (`Persistence.setCalendarService`) stays exactly as-is; type it with a small local interface, not an import from `schedule-services.mts`.
- **`StoredState.tasks` is NOT `NimbusTask[]`.** `JSON.stringify` turns every task's `Date` fields into ISO strings; typing it as `NimbusTask[]` would be a live lie (T-6/§G in `docs/typescript_migration.md`). Use `Array<Record<string, unknown>>` and re-coerce through `_prepTask` on read, exactly like the runtime already does.

"""
Regression guard for Phase 4's response_model= additions (docs/typescript_migration.md).

FastAPI's response_model serializes the return value THROUGH the Pydantic model —
any dict key the handler returns that isn't declared on the model is silently
dropped (not an error). A typo'd or forgotten field name is invisible to
`npm run typecheck` (that's the frontend) and to a naive "does it 200" test.
This test builds a synthetic dict with the EXACT key set get_tasks's `data.append({...})`
literal produces (brain.py), constructs a TaskDTO from it, and asserts the
round-tripped key set is unchanged — so a field silently dropped by the model
fails this test immediately, without needing a live database.
"""
import os

os.environ.setdefault("NIMBUS_PG_POOL_MIN", "0")

import brain  # noqa: E402


SAMPLE_TASK_ROW = {
    "id": "abc123",
    "text": "Order abc123",
    "start_date": "2026-08-01T07:00:00",
    "end_date": "2026-08-01T15:00:00",
    "original_start_date": "2026-08-01T07:00:00",
    "original_end_date": "2026-08-01T15:00:00",
    "user_scheduled": False,
    "PRODUCTION_LINE": "Line 1",
    "MATERIAL_DESCRIPTION": "Widget",
    "MATERIAL_NUMBER": "MAT-1",
    "ORDER_QUANTITY_(GMEIN)": 500.0,
    "COLOR": "WHITE",
    "PLANT": "5512",
    "ORDER": "ORD-1",
    "ORDER_Y": 1.0,
    "RUN_TIME": 2.5,
    "FORM_SIZE": "MD",
    "notes": None,
    "firmed": False,
    "row_version": 42,
}


def test_task_dto_round_trips_every_field_get_tasks_emits():
    dto = brain.TaskDTO(**SAMPLE_TASK_ROW)
    out = dto.model_dump(by_alias=True)
    assert set(out.keys()) == set(SAMPLE_TASK_ROW.keys()), (
        "TaskDTO's declared fields no longer match get_tasks's dict literal — "
        "a field was renamed/dropped on one side only. Diff: "
        f"missing={set(SAMPLE_TASK_ROW) - set(out)}, extra={set(out) - set(SAMPLE_TASK_ROW)}"
    )
    assert out == SAMPLE_TASK_ROW


def test_bulk_update_result_round_trips_db_shape():
    sample = {
        "status": "ok", "updated": 3, "persisted": 3, "failed": 0, "invalid": 0,
        "not_found": 0, "invalid_ids": [], "not_found_ids": [], "stale": [],
        "versions": {"abc123": 43}, "error_code": None, "cause": None,
    }
    out = brain.BulkUpdateResult(**sample).model_dump()
    assert out == sample


def test_openapi_schema_includes_new_components():
    schema = brain.api.openapi()
    names = set(schema.get("components", {}).get("schemas", {}).keys())
    for expected in ("TasksResponse", "TaskDTO", "LinkDTO", "TaskUpdateResult",
                     "BulkUpdateResult", "TasksRefreshResponse", "BaselineCorrectResult"):
        assert expected in names, f"{expected} missing from OpenAPI components.schemas"
