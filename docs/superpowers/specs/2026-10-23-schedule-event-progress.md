# schedule_event progress ledger (2026-10-23)

`schedule_event` is an append-only per-order change history written in the same transaction as every planner-visible order write (planner save, note, Excel/SAP ingest, routing holds/recompute, purge/vanish, distribution), kept 14 days by a nightly batched sweep, read through `GET /schedule-events/{plant}/order/{order_id}` and shown as a History section in the order Inspector. Plan: `C:\Users\PJ29587\.claude\plans\draw-up-a-plan-greedy-quill.md`. Branch: `feature/schedule-event`. Decisions (owner, 2026-10-23): D1 one row per order per change grouped by `action_id`, field-level `changes` JSONB with only changed fields; D2 fail-open under `SAVEPOINT sched_ev`, counted in `DIAGNOSTICS["schedule_event_write_failures"]`; D3 retention 14 days (`system_settings.schedule_event_retention_days`, clamp 1-60); D4 v1 scope = save, note, ingest, routing holds/recompute, purge/vanish, distribution (restore/repair/resync are P2); D5 batched nightly sweep, not partitioning; D6 order by `id DESC`, `at DEFAULT clock_timestamp()`; D7 op vocabulary `create|modify|remove` (deploy regex avoids update/delete words), no CHECK on `source`; D8 actor = `x-user-email` (spoofable, like `admin_audit`); D9 diff DB-typed before vs DB-typed after, never the wire payload.
