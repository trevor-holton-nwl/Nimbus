# Alert Profiles revamp: Matrix | Inbox monitor, two-tier editor, profile-owned Gantt colors

Status: design settled 2026-10-30 (plan rev 3). Research, three adversarial reviews and three mockup rounds with the owner are done. Mockup of record: https://claude.ai/artifact/V5dMeUrzrVwRcWP9vv6QXF (version 6); repo copy `docs/superpowers/specs/assets/2026-10-30-alert-profiles-mockup.html` (throwaway design reference, not product code). Builds on `docs/superpowers/specs/2026-10-20-alert-monitor-design.md`. Branch `feature/alert-profiles-revamp`; ledger `docs/superpowers/plans/2026-10-30-alert-profiles-revamp-progress.md`.

## Context

The Alert Monitor shipped 2026-10-20 (rev 3 Overview band) and grew into a page that stacks a 3-row header, a 3-panel Overview band, Top fixes, a focus chip, then nested group cards with sentence-long rows, with four overlapping filter mechanisms (profile, focus set, Overview narrow, Group by/Sort). The owner: "a scrolling nightmare… so many groups/suggestions that are hard to triage… hard to digest and too wordy". The profile editor shows ~48 controls for a one-rule profile (38 of them checkboxes), has a severity option ("Warnings and errors") that filters nothing, and expresses the day window as two signed integers.

What the owner loves and keeps: creating/assigning profiles, Top fixes, the "Move to an open machine" dialog (731ecd9) **unchanged**, and from the mockups: the **Matrix board** and the **Inbox**.

**Surprise from research: the Gantt already fills bars by alert category** for profile-matched orders (`profile-match-<cat>` classes from `Timeline._profileMatchClasses`, six global `--bar-pm-*` tokens, severity ring). But the colors are global CSS, not owned by the profile; "All alerts" highlights nothing; and the Alert Monitor's focus *replaces* the fills instead of adding to them. So the "color the Gantt by profile" ask is: make the profile own per-group colors, make the active profile the thing planners set up, and make the Gantt, Legend and minimap read the profile's palette.

**Second surprise (mockup research):** NIMBUS already has the primitives the Matrix needs. Machines carry `wc_group` ("Workcenter Group") in master data and the Labor grid already groups rows by it with sticky group headers; the Dashboard Lateness heatmap already renders every machine worst-first with stepped severity tints and a sticky header; `VirtualList` already backs 36 px rows on the Machine Status card and the Alert Monitor's group-by-None list. Only "fold quiet rows" is new.

## Goals, non-goals, anti-goals

Goals
- A profile owns its alert groups (seven, each on/off plus a color from a fixed palette) and the Gantt, Legend and minimap paint from that profile.
- A two-tier editor: seven group rows on top, per-group narrowing behind a collapsed Fine-tune disclosure.
- A monitor that is one filtered set shown as an Inbox or a Matrix, with one-line rows and short tags.
- Focus ("Show on Gantt") outlines only the orders in view, on top of the profile fills instead of replacing them.

Non-goals
- A per-user color override, custom-named groups, a role-default profile UI (deferred).
- Redesigning the "Move to an open machine" or Acknowledge dialogs (D9).
- A canvas bar layer, matrix row virtualization, a density preference.

Anti-goals (things this must not become)
- A new backend domain or a rewrite: in-place edits and reuse of existing primitives (D6).
- A point-ramp heatmap: the Matrix shows counts tinted by worst severity, never points.
- Plant or machine chip selectors: 70+ machines and 50+ plants mean searchable/filterable controls and group roll-ups only.
- A second place where colors live: one palette, one set of tokens.

## Calls made during planning (flagged, not re-asked)

- **Field name is `categories`, not `groups`.** UI copy still says "alert groups".
- **Contrast gate is perceptual (ΔE2000), not WCAG 3:1** (no 8–10 fills can be 3:1 apart from each other and from the blue/red bars). Gate: fill/text ≥ 4.5:1; fill pairs ≥ ΔE 15; ≥ ΔE 6 under red-green CVD (Machado 2009 severity 1.0, named in the test); ≥ ΔE 15 vs `--bar-standard`/`--bar-firmed`; fill vs `--bg`/`--bg-elev` ≥ 1.8:1 in light (sky/sand darkened); warn ring ≥ 2:1 or equals text; white keyline documented as the err-ring carrier where `--err` < 2:1.
- **Matching rule:** switches decide which families are in the profile; rules narrow. "Applicable" pinned at category level (`categoryOf`, never `ALERT_CATEGORIES[c].includes`). Existing rules-only profiles match identically (proof + property test).
- **Focus outline is ink, not red** (`--err` equals `--bar-firmed`): `outline: 2px dashed var(--fg); outline-offset: 1px`. Minimap: category fill + 1 px `--fg` keyline.
- **Focus intersects with the profile being viewed**; fully-acknowledged orders excluded unless the pref; "Outlined: N · Clear" chip on the Gantt toolbar + Escape when nothing is selected.
- **Matrix cells are counts tinted by worst severity** (`--err-soft`/`--err`, `--warn-soft`/`--warn-text`), the Lateness-heatmap pattern, never a point ramp (Alert Monitor "counts, not points" rule). Group-color dots inside the cell say which groups are present.
- **Quiet rows fold** per work-center group ("Show N quiet machines"); this is the one new interaction with no precedent.
- **Day lens columns are work-center groups**, never 70 machine columns.
- **Short tags are new locale keys** `alert.tag.<type>` (about 32 types × 5 locales) with the same `msgVars` as the message; the full message stays in the expanded row and the Gantt hover. Vocabulary gate applies.
- **Material on a row** comes from the order (`Store.tasks[id]`'s material description field; queued alerts carry `taskId` too). An alert with no order (machine/day `overload`, `closed`, `plant_no_timezone`) shows the machine/day instead.
- **Day presets:** Any · Overdue · Next 3 · Next 7 · Next 14 · Custom.
- **W0 is a checkpoint that already happened** (three mockup rounds). W0 now only commits this design doc and the mockup HTML.
- **Branch from the current `main` tip**; W3 and W4 sequential (both touch the five locale files).
- **Top fixes empty state** says "No fixes touch the alerts in view" (reverses spec D10; D11 reversed by W4; both in the rev-4 note).

## Shared contract (both halves build on this)

```ts
// frontend/platform/types.mts
type AlertCategory = 'capacity'|'conflicts'|'calendar'|'setup'|'planning'|'late'|'exceptions';
type PaletteName = 'amber'|'orange'|'magenta'|'violet'|'teal'|'sky'|'slate'|'sand'|'stone';
interface ProfileCategory { on: boolean; color: PaletteName }
type ProfileCategories = Record<AlertCategory, ProfileCategory>;
interface AlertProfile { …; categories?: ProfileCategories | null }   // null/absent = legacy, derive from rules
```

- `insights/alert-profiles.mts` exports: `ALERT_CATEGORY_ORDER` (one list; `CATEGORY_ORDER` and `MONITOR_CATEGORIES` alias it), `PALETTE`, `DEFAULT_CATEGORY_COLORS` (capacity amber, conflicts violet, calendar teal, setup magenta, planning orange, late slate, exceptions stone), `effectiveCategories(p)`, `ruleAppliesTo(rule, cat)`, `profileMatches` (category on AND (no applicable rules OR some applicable rule matches)), `categoryColorDecls(p)` → the full 21-key map using `DEFAULT_CATEGORY_COLORS` for built-in/null (never `{}`), `profileCategoryCounts(...)` (one pass).
- `insights/alert-profile-matches.mts`: `AlertProfileMatchSet` gains `orderIds` (union of `alertOrderIds`, **also in the `__all__` branch**) and `focusIds` (focus ∩ `orderIds` minus fully-acked unless pref), applied to both `current()` and `view()`; `_applyFocus` **no longer replaces** the fills; under `__all__` `sevByTask` holds err only (D8). `applyCategoryColors(el, profile)` writes/removes all 21 keys via `style.setProperty`, no-op without `document`. Exposes `focusTaskIds()`.
- CSS: `--pal-<name>`/`-fg`/`-ring` in **both** `:root` and `body.dark`; `--bar-pm-<cat>` = `var(--pal-…)` in both; inline overrides on `document.body` (Gantt, Legend, minimap) and on `#alerts-tab` (full map for the viewed profile). Editor swatches read `--pal-*`.
- Backend: `alert_profile.categories JSONB NULL` + `CHECK jsonb_typeof = 'object'`; complete 7-key map, each `{on, color ∈ PALETTE}`, ≥1 on; with it `rules` may be `[]`; without it the old ≥1 rule stays. `CATEGORIES`/`PALETTE` frozensets pinned to the frontend literals by a pytest.
- Editor: `draftFromProfile` sets `draft.categories = effectiveCategories(p)`; `profileFromDraft`, `_revalidate`, save payloads, `_copyGo`, Duplicate carry the full map; `liveMatchCount` passes it; `blankDraft` = all seven on, default colors, `rules: []`.
- Monitor filter state (session-only): `{machines: Set, wcGroups: Set, days: Set<dayKey|'overdue'|'later'|'none'>, categories: Set, q: string}`; both views read it; chips render it; persisted `alertMonitorView['*'] = {view: 'matrix'|'inbox', lens}`.

## Appendix: Context + things learned along the way

Things learned during research and mockup rounds that a builder should not have to rediscover:

- **The Gantt already fills bars by category.** `Timeline._profileMatchClasses` emits `profile-match-<cat>` classes, backed by six global `--bar-pm-*` tokens plus a severity ring. The work is making the profile own the colors, not inventing a fill mechanism.
- **Alert Monitor focus currently REPLACES the fills.** `_applyFocus` swaps the profile-match set for the focus set, so focusing hides the category colors. W4 makes focus additive (outline on top of fills).
- **`--err` equals `--bar-firmed`.** A red outline therefore vanishes on firmed bars, which is why the focus outline is ink (`var(--fg)`, dashed) rather than red.
- **`_buildSet` short-circuits the built-in All-alerts profile before collecting order ids.** `orderIds` must be filled in the `__all__` branch too, or focus and D8 have nothing to intersect with.
- **A `var()` inside an inline custom property resolves on the element it is declared on.** So profile color overrides must be written on `body` (not `html`/`#alerts-tab` alone) for them to follow `body.dark`; the `--bar-pm-<cat>` indirection through `--pal-*` depends on this.
- **`machine.wc_group` already groups rows on the Labor grid**, with sticky group headers: the Matrix Machine lens reuses that precedent and the `Store.masterLinesForPlant(plant)` accessor.
- **No "collapse quiet rows" behaviour exists anywhere yet.** The quiet-machine fold is the single interaction without precedent; keep it small and measure it.
- **The migration runner's destructive-word filter trips on ALTER, and `-AllowDestructive` applies to every pending file.** Hence `promote-azure -Only 2026-10-30-2 -AllowDestructive` after a dry run, so unrelated pending ALTER files are not swept in.
- **`2026-10-30-1` is already used by two migrations**, which is why the new one is `2026-10-30-2`.
- The Overview band's charts are not lost: they become the Matrix row bars (Where / When / What) and the Inbox facets; only its pure data helpers (`overviewData` buckets, `dayKeyOf`, `NONE_KEY`) survive.
- No perceptual palette of 8 to 10 fills can be 3:1 apart from each other and from the blue/red bars, hence the ΔE2000 plus CVD gate instead of a WCAG 3:1 rule.
- Mockup history: three rounds with the owner; version 6 of the artifact is the record (the plan text still said version 5).
