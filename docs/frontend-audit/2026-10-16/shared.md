## Independent review closure — final shared round

Read `review-shared.md` and reproduced all three targeted failures before changing production code: split restore delivered the previous segment envelope to reconcile, legacy mixed-plant history falsely removed remote/unknown rows, and the 10,000th local order was absent from search.

- **R-SHR-01 fixed:** restore clears `scheduleSegments` in the same date patch before real Store normalization, then delegates placement to existing Engine.reconcileRestored. The regression uses real Store, real Engine, a hydrated partial-allowed calendar with 08:00–16:00 windows and a pinned plant clock. Six-hour restore produces a fresh split aggregate ending at the requested finish and Undo restores the previous valid aggregate. Two-hour changed-runtime restore becomes continuous; ten-hour restore spans two days. Undo keeps the prior finish and re-derives using current runtime in changed-runtime cases. No historical pieces are blindly replayed through today's calendar/runtime.
- **R-SHR-02 fixed:** new snapshots carry `schemaVersion: 2` and per-task PLANT. Historical comparison scopes both sides. Legacy ownership resolves by captured PLANT, known version-2 snapshot scope, live task PLANT, then a unique owner across master-data lines/line settings/live tasks for the recorded machine. Ambiguous or missing ownership is omitted with a localized count; unknown history never produces an unsupported “identical” claim. Known removed local rows remain removals, including an explicit-PLANT row whose machine is no longer known. Existing IndexedDB history is preserved.
- **Compatibility cleanup:** Dismiss-all uses a shell event listener instead of adding an inline handler. Both opener references are closure variables, eliminating accidental public/private cross-controller growth. The no-shadow declarations in the shell test were removed.
- **Four deliberate existing public read dependencies:** `Store.tasksForSelectedPlant` centralizes authoritative selected-plant indexing/capture/compare/restore scope; `Engine.firmingStatus` centralizes manual/frozen/running protection; `Store.masterData` and `Store.lineSettings` supply evidence for conservative legacy machine ownership. The existing first-match `getPlantForLine` cannot prove uniqueness for ambiguous legacy lines. Root owns the reviewed compatibility-inventory update; no scanner weakening or hidden dependency workaround was introduced.
