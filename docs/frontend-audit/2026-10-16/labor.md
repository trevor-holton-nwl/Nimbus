## Decisions and API

- The split denominator remains **all open machine-days in the entire group/week**. Pinned cells keep their value and do not redistribute their difference to unpinned cells. Example: 70h / 7 open slots produces 10h per automatic slot; a 3h pin remains 3h. This preserves the stated override behavior; Inputs explicitly explains that resulting line totals may differ from group totals.
- Existing one-decimal split rounding remains unchanged.
- A blank aggregate clears its automatic descendants. A blank daily cell deletes its stored value and uses calendar availability. Explicit zero remains a stored zero.
- Daily reset uses automatic group split if one exists for the open day, otherwise calendar fallback, including closed days and lines with no group.
- Existing individual POST endpoints retain compatibility, including existing legacy source values; the frontend now uses the stricter batch endpoint.
- `POST /labor-plan/batch`: authenticated and plant-scoped like existing Labor writes. Body `{subnetwork, plant, cells:[{wc_group,period,avail_hours}], line_cells:[{machine,day,avail_hours,source}], intent}`. Intent is `reconcile`, `explicit`, or `undo`; omission defaults to reconciliation when aggregate cells exist, otherwise explicit. Response `{aggregate:{upserted,deleted}, lines:{upserted,deleted,rows,applied,skipped}}`; `rows` contains canonical values/provenance for every submitted line key (null tombstones for absence), `applied` contains actually mutated machine/day keys, and `skipped` contains current overrides preserved by automatic reconciliation. Automatic upsert/delete conditions execute in SQL and recheck current source after concurrent lock waits; explicit daily reset and Undo remain intentional writes. New endpoint validates finite nonnegative hours, actual ISO week/date keys and `auto_split`/`override` provenance. Writes and audit rows share one transaction. No migration/schema changes.
- No scheduling demand, finish anchoring, production calendar calculation, shared Store selection identity, deployment or live environment changes.

## Remaining opportunities and limits

1. **LAB-O01 - cross-client concurrency, narrowed:** Automatic batch reconciliation now preserves current server overrides, including pins committed while its SQL waits on a concurrent transaction. Canonical acknowledgements reconcile the browser cache, and Undo excludes skipped cells. General conflict detection remains deferred: simultaneous explicit daily edits/resets, aggregate edits or intentional Undo still have no version/precondition contract. A future change should return per-cell versions and reject batches on changed expected versions. The old individual POST routes retain their compatibility behavior.
2. **LAB-O02 - group catalog usability, implemented:** Persistent case-insensitive group search filters checklist names without dropping hidden selections. The input survives toolbar refreshes and reopen; Escape closes the dropdown and returns focus to its trigger. Behavioral coverage added. Production-line search remains the existing separate control.
3. **LAB-O03 — dense daily grids:** 70 lines x 112 days creates 7,840 inputs. Measure actual browser layout/input latency first; if needed virtualize columns while retaining logical keyboard navigation and exact exception destinations. No scale/browser performance claim is made here.
4. **LAB-O04 — rounding reconciliation:** Equal slots are individually rounded to 0.1h, so automatic totals can differ from aggregate even without pins. A later explicit policy could distribute residual tenths in stable machine/date order and expose a reconciliation difference. Current rounding behavior intentionally retained.
5. **LAB-O05 — legacy API validation:** Existing two single-table endpoints still accept legacy `manual` source strings and have eight pre-existing malformed-payload xfails. Batch validation is strict; unifying legacy validation would require an explicit compatibility change and updating those tests.
6. **LAB-O06 - localization, new copy covered:** All UI text introduced or changed by this audit now uses `Util.t`, including loading/retry, scope/reconciliation explanations, reset/save/preservation feedback, accessibility labels and group search. Root supplied all 30 keys in the five locales and owns locale-completeness verification. Untouched legacy Labor copy remains a separate whole-surface localization opportunity.

## Independent review remediation

The four findings in `review-labor.md` are addressed in implementation; independent closure remains with the reviewer. The review retains the evidence from earlier revisions.

- **RLAB-01:** Added the actual `LaborPlanning.init()` subscriber/Store plant-switch reproduction with a delayed first POST and a queued second group edit. The regression failed before the fix (the queued payload included the pinned Monday). Plant changes now request a refresh instead of deleting committed caches immediately. Render drains the latest write queue, checks its generation, and only then invalidates the aggregate read cache. Thus each queued operation snapshots the result of preceding successful edits. The regression verifies pin exclusion and exact Undo of original group hours, a previous automatic value, and absent daily cells after switching away/back. Aggregate fetches also guard generation/revision before caching.
- **RLAB-02:** Success and failure tests reproduced next-cell draft loss; another test reproduced replacement of a third draft while two edits were already queued. Save acknowledgements now patch only their daily cells in place, including source styling, color, title and saved baseline. Input identity, current focus and a later uncommitted value are preserved; input revision plus submitted value protects newer drafts in the same cell. Undo patches clean cells in place rather than rebuilding Line Plan. No save callback forces focus backward.
- **RLAB-03:** Both stale-read pin overwrite and pin deletion were reproduced against actual PostgreSQL before the fix. `reconcile` mutations now condition their conflict updates/deletes on current `source <> 'override'`; `explicit` and `undo` remain unconditional intentional operations. The response returns canonical rows, actual applied keys and preserved/skipped overrides. The client uses those canonical rows and includes only actually applied keys in Undo. Audits record actual counts and the preserved-override count, rather than requested row counts.

Real PostgreSQL acceptance includes absent and automatic initial reads followed by another client's committed pin, automatic upsert and clear, explicit reset to a split or calendar fallback, intentional Undo restoration, and three **controlled overlapping transactions** (insert, update and delete). Tests hold client B's pin transaction open, verify via `pg_blocking_pids` that client A actually waits on B, then commit B and assert the pin survives A's conditional write and appears in its canonical acknowledgement. Existing aggregate/line/audit rollback coverage still passes. Focused backend file: **16 passed**, including all these cases.

Final review-fix checks: build passed; combined Labor Node tests **27 passed**; focused ESLint/Ruff and diff whitespace checks passed; compatibility Python run **211 passed, 8 existing xfails**, no DB skips. `check:legacy-surface` reports no Labor additions and three removed Labor inline handlers; remaining violations were outside this package and sent to root. Retry is now bound with a DOM listener instead of a new global inline bridge consumer. Browser interaction/visual evidence remains pending and is not replaced by these deterministic harness tests.


### RLAB-04 Aggregate draft protection

Five new behavioral regressions were confirmed failing before their respective fixes: successful and failed acknowledgements replacing a later same-cell draft; two queued writes replacing a third draft; validation refresh deleting an unrelated draft; and a later clear matching the old saved baseline being mistaken for a clean input. Aggregate inputs now track saved baselines and input/submission revisions. Acknowledgements update only clean inputs or the unchanged submitted value, always advance the saved baseline, and preserve later drafts and focus. Invalid input restores its own submitted value without overwriting unrelated drafts; intentional Undo still updates clean cells.
